# 核心演进 — 交付计划

## 用途

[核心方向](core-direction.md)维护产品与架构承诺。本页维护分阶段交付、实现依据和验收条件。现有 [Sessions](../how-it-works/sessions.md)、[Prompt Assembly](prompt-assembly.md) 和 [Module Contracts](module-contracts.md) 描述当前版本，不要求保留耦合的运行时所有权。

## 交付计划：公开 SDK 执行闭环

本页定义交付目标和验收条件。工作状态与运行结果按[开发工作流](../contributing/development.md)跟踪，不在这里追加日期检查点或进度表。修改规划不等于启动实现。

### 可观察结果与阶段

第一个结果是仅使用公开 SDK 的普通 Rust 调用程序，以及使用同一 API 的薄 CLI。在可丢弃的普通目录中，Agent 检查文件、修改一个小程序、运行其测试并返回可检查结果。关闭并重开 Session 后继续工作，同时验证取消与异步清理。在 Git 和非 Git 目录验证同一核心行为，不隐式初始化仓库。

| 阶段 | 交付物 | 证据 |
|---|---|---|
| 1. 可用单 Agent | 公开调用程序和薄 CLI；明确模型连接、真实文件／命令工具、多调用 Step、持久接纳／结果、查询／观察、取消、有界输出和重开 | 一个有用的真实任务及其判定器；针对持久化、授权、输出和清理的检查 |
| 2. 独立 Agent 与 provider | 同一 Session 内两个独立初始化、使用不同 provider 的 Agent；直接通信和续派；共用配置解析，不修改全局配置 | 真实委派任务；三种要求的线路协议均有验证；不 fork 父历史；同协议连接选择；保留支持的思考／服务设置，或拒绝不支持的显式值 |
| 3. 持久等待与编排 | 提问／延后授权可持久化，并在重开后匹配续接；小型 SDK 调用程序验证受控讨论和定时器／外部输入 | 等待时不推理；重复输入不重复开工；过期回复／回调不能推进替代执行；示例复用已有执行器 |

阶段是交付边界，不是不同运行时。从一开始按这些场景设计身份、输入语义和所有权，但只实现当前阶段需要的路径。首个有用执行之后尽早推进阶段 2，暴露单模型、单上下文和仅根 Agent 可运行等假设。阶段 3 的示例不要求生产级调度器、Team 平台、server 或新 UI。

第一阶段包含最小本地 CLI，完整交互打磨和其他宿主后置。每阶段的必要正确性屏障完成后才能宣称交付。首次模型实验可以早于全部持久化工作完成，但不能代替缺失契约的验收。

### 实现归属

Session SDK 持有执行和持久状态，provider 适配器负责协议转换，验收入口检查公开 SDK 和宿主边界。下一阶段的宿主改动见模块归属和客户端计划。[模块契约](module-contracts.md) · [交互客户端计划](interactive-clients.md)

### 实现时可决定的事项

Rust 名称／签名、事件封装／schema、队列／输出数值限额、解析器和检查点布局，仍是核心方向约束下的工程选择。宣称有界运行前，记录具体限制和超限行为。改变身份作用域、强制 Task 对象、默认 fork、全局模型联动或削弱持久化，均需明确修改基线。

### 开发工作流交付

[工作流交付要求](../contributing/development.md#重构中的工作流交付要求)属于同一次重构。阶段 1 包含全新会话交接和可重复的公开 SDK／CLI 验收入口；阶段 2、3 沿用该入口，扩展协议、独立 Agent 和恢复验证。任务报告、测试入口、PR 指引与 CI 应随交付行为一起调整。不等运行时全部完成后才补工作流，也不另建自动化平台。

所选模型、连接输入、凭据及付费测试限额见[真实协议验收](../contributing/testing.md#真实协议验收)。运行记录保存在验收产物中，不写入本设计计划。

## 运行时与 Harness 边界

默认 Harness 与自定义调用方都通过 SDK 创建、输入、配置、推进／控制、查询和观察。它们可以选择上下文材料与激活策略，不能绕过持久接纳、工具授权或清理。普通内部职责可保留为一个 crate 内的内聚模块。只有实际变化的外部能力才需要适配器，不为每次内部调用建立包和注册表。

| 未来用途 | Harness 增加什么 | 运行时提供什么 |
|---|---|---|
| 独立委派 | 任务简报、选定材料、接收者选择、结果收集 | 新 Agent 的独立上下文、稳定地址、执行与消息事实 |
| Team／受控讨论 | 成员、可选任务板、发言／结束规则 | 同一套 Agent 和直接投递；必要时只入箱而不激活 |
| Always-on 助理 | 持久定时器／接入、跨 Session 路由、Memory 选择、通知策略 | 可重开状态、关联输入、等待、有界执行、可查询结果 |
| 围绕工作的编排 | 外部工作身份、派工、审核／完成规则 | 输入和结果的关联引用，不把 Agent 空闲视为工作成功 |

长期助理名称可以随时间路由到不同 Session。迟到的答复或批准仍须指向原 Session、Agent 和待决请求，不能随名称转交给最新会话。业务记录可以在 Session 日志之外；SDK 幂等和观察能力支持宿主跨越该边界对账，不要求分布式事务。

## 输入、推进与观察

整合创建和提交前，定义幂等作用域与命令身份。在约定的保留范围／作用域内，同一重试返回原回执，同一 key 配不同内容则失败。来源身份取自可信调用边界，不从模型生成的消息正文取得。

分别记录输入接纳、进入准备好的 Step 和执行结算。默认发送操作可以组合投递与激活请求，受控 Harness 可先存入输入而不运行模型。运行时查找、批处理和投递回执是确定性操作。收到上下文不隐含扩大工作范围或批准动作。

每个 Agent 使用一条推进链，Session 只短暂串行提交。模型调用、工具 I/O 和慢订阅者不能跨 await 占住 writer。约束待处理工作，定义接纳拒绝／背压。持久查询／观察游标支持丢失回调后重连；临时流式 chunk 不必全部持久化，但已提交事实必须仍可查询。

## 模型解析、上下文与交接

使用单一配置解析入口。选中的 Preset 提供行为与初始默认值，Tier 提供路由／设置默认值，显式 Agent 选择优先。按明确配置的连接／模型解析，在派发请求前绑定结果。修改一个 Agent 不改变其他 Agent，也不静默重写其默认值。配置变化在明确安全边界生效。

适配器能力描述与校验共同服务 SDK 调用者、用户界面和模型可见的 Agent 工具。思考与服务选项独立；供应商特有值必须声明、校验和记录，不静默忽略或强行套进通用排序。区分请求设置、实际发送的有效设置和可选 provider 回报。显式不兼容选择必须失败，未获回报的设置不能声称已被确认。

独立初始化只提供调用者选定的材料。复用 Agent 可以保留已有项目认识，但不构成默认 fork 对话的理由。切换模型／连接时，不悄悄移植不兼容的继承选项。记录有效选择及其来源。

保留 Prompt 资源以及忠实重建所需的 provider 可见准备内容。已接纳内容和工具结果视图只保存一次，用引用和请求边界表达每个 Step，不复制完整历史。重放历史不重读可变工作区文件，也不重渲今天的 Prompt 模板。上下文交接记录前驱和选定材料，先提交后继再切换。交接失败时保留可解释的原状态。

上下文段活跃期间保持已提交前缀稳定。大结果首次接纳时即限制视图大小并提供引用。实际字节或 token 压力升高时，在完整工具批次或用户输入之前选择切点，由一次有界的摘要请求交接较早的工作。保留当前用户输入、最近完整的批次及其供应商原生重放内容。预算允许时，摘要请求沿用已经缓存的前缀。验证替换后的请求再提交后继段。原始日志和输出仍按现有保留和授权规则可用。摘要失败时，已提交的原段继续保持权威。

本地压力尚未达到阈值时，供应商仍可能在开始输出前拒绝已准备的请求。开启自动压缩后，在这个边界允许生成一次交接，并发出一次较小的替换请求。被拒尝试单独记入日志，当前输入继续保留。开始输出后发生的故障沿用已有的终止处理。

已结束的用户轮次应整轮保留，或由交接记录其结果，包括已经交付的回复。仍在进行的工作保留原始输入。交接中可以附一小节纠偏，每条根据已观察到的失败或用户明确纠正，给出证据和对剩余工作的具体调整。关键证据保留最短且已核验的定位方式，例如文件路径和符号，或输出 ID 和字节范围。省略依据薄弱的推断。恢复后的 Agent 可以用保留的证据核验尚不确定的判断。回退跨过被摘要的工作时，相关交接失效，并恢复仍有效的历史。

## 持久化、副作用与持久等待

每个 Session 从一个权威追加日志和一个 writer 开始，包含跨进程互斥与过期所有者隔离。有界记录大小和外置输出支持流式恢复。小型可丢弃索引可服务 Agent 查找、命令去重和事件定位；其他落盘索引／检查点根据实际恢复和查询测量选择。

Session 使用一份权威日志。符合条件的正常关闭可以把同一文件发布为带内嵌恢复检查点和独立 gzip 压缩帧的日志，后续记录追加到明文尾部。压缩帧和检查点元数据都在日志内。恢复视图损坏或不可用时，从可读的事实重建。读取历史时校验打开的压缩帧。

只读日志扫描使用固定的文件句柄和已提交边界。获取边界时可以与 writer 协调。读取和生成视图期间，writer 可以打开会话并继续提交。恢复某个 Session 的 writer 时，其他 Session 仍可访问。

历史读取共享已提交索引中的不可变轮次归属和消息预览。查询复制所需的证据，提交只更新受影响的索引项。

内嵌检查点不可用并已通过回放重建后，正常关闭即可替换检查点，独立于日志压缩的体积阈值。替换从已提交事实生成并原子发布，仍受检查点大小限制。

Session 列表可以从封存日志独立读取摘要和 Agent 状态。列表数据缺失或不可用时，读取已提交事件。

明确定义提交单元与确认屏障。确认引用前，其输出内容必须已持久保存；副作用之前有派发意图，确认之前有结算。只恢复可识别的不完整尾部，拒绝已提交历史损坏。必要写入失败时停止依赖执行。

被请求的动作、已知派发的动作和已确认结果是不同事实。副作用可能已经发生时，报告未知结果。provider／工具适配器可以对账或使用外部系统支持的幂等机制；通用重试不能重复任意副作用。取消／替代后，按绑定的执行身份拒绝过期回调。

只在已定义边界持久保存可恢复等待，例如提问或派发前授权。保留请求身份、精确目标动作、适用时的参数／工具绑定，以及回复关联。异步回调可处理短暂等待，但不是持久记录。恢复时验证请求仍待决且仍适用；重复或过期答复不能重复派发。不恢复挂起的 Rust future 或任意执行到一半的操作系统进程。

关闭 Session 运行资源会停止／结算所属执行，并在必要写入后释放 writer，不宣称业务任务成功，也不擦除待处理事实。重开为获准的 Harness 调度重建这些事实；无人值守工作是否继续由明确宿主策略决定。

## 工具、工作目录与资源预算

前台和后台工作共用执行与输出生命周期。ToolCall 只结算一次：最终结果或 Job 句柄，Job 完成是后续事实。父 Turn 结束不隐式结束子 Agent；取消范围遵循明确所有权和控制，不由地址拼写决定。

stdout／stderr 经有界缓冲、解析器状态、诊断和视图流式处理。从通用预览和有用的明确构建／测试解析器开始。标记过滤或采集不完整，并提供输出引用／范围。承诺完整采集前，确定配额与磁盘满行为；明确停止或排空／丢弃，避免管道填满后死锁。按承诺周期保留引用。

使用普通目录，每次执行显式指定 cwd 和环境。共享工作区默认值不提供事务隔离；保留过期编辑检测，对已知冲突工具排序。worktree 和 Git 保持用户／Harness 的选择。SDK 不接管全局 cwd、环境变量、信号处理、日志或无关进程。

模型请求、工具进程、活动上下文、待处理输入、输出存储和订阅者是不同资源。等待人类输入时释放模型容量。共享不可变 Prompt／工具资源和适用的客户端，避免每个 Agent 复制完整历史，允许不活跃状态按需重建。Harness 可优先处理人类续问，但必须遵守明确的硬资源限制。

默认本地入口选择核心方向规定的可信本地策略，嵌入宿主可以替换。不要重新把“默认拒绝是否合适”列为产品前置待决项，也不以策略 DSL 为前提；报错、缺少必要决定和取消仍不构成副作用授权。

## 验证与测量

从成熟 benchmark 选择三到五个 case，不另造评测框架。先做一个成本低的真实 case，再扩展。保留原任务／环境／判定器，记录必要适配。小型清单或适配器属于开发工具，不进入 SDK 运行依赖。[Harbor 任务格式](https://docs.harborframework.com/tasks/overview)可作为候选。

记录 provider／连接、模型、思考、服务、预算和环境，使比较有意义。检查输出产物、原判定器结果、进程退出状态、已提交执行事实和模型已接纳输入，不断言模型措辞或偶然工具顺序。区分环境／基础设施失败、运行时失败和 Agent 未完成任务。少量 case 用于诊断，不构成排行榜结论。

实现对应边界时选择针对性测试：

- 重复创建／输入与回执丢失；错误目标、重复或过期回复；不重复启动 Agent 推进链。
- 竞争 writer、不完整尾部与已提交损坏、派发／结算前后的磁盘／写入失败、未知副作用、过期回调。
- 多个同协议连接、独立 provider 选择、不支持的思考／服务设置、不修改其他 Agent。
- 独立 Agent 上下文、受控激活、直接且获准的消息、不强制 fork 父历史。
- 重开的 provider 可见前缀、模板／配置变化、交接失败、精确的首次接纳输出视图。
- 多调用配对、冲突编辑、授权拒绝／报错／延后／取消、大输出、清理竞态、慢或断开的观察者。
- 跨重开的持久等待，以及复用同一执行器的最小外部定时器或受控讨论调用程序。

尽量使用真实存储、授权和执行路径，仅替换确定性故障注入所需的依赖。真实模型不一定按要求产生多调用，因此必要时将真实任务与针对性批次测试配对。仅 mock 或一次真实成功都不能证明所有失败保证。

测量空闲和活跃内存／CPU、冷打开／恢复、追加与上下文准备延迟、大输出和并发 Agent。区分 SDK 进程、工具和 benchmark 容器的资源。记录未缓存输入、缓存读／写、输出、实际／估算费用和用户可见延迟，区分首次探索与连续工作。不用命中率或累计 token 替代这些成本，不承诺固定 provider 缓存命中率。

所需检查、显式 feature 选择和证据报告遵循[测试工作流](../contributing/testing.md)。直接 API 探测不代表 SDK 验收通过。
