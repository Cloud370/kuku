# Web 客户端

浏览器客户端是一个工作台，每个 Session 都有自己的页面和地址。它保留人们已经熟悉的对话语法，并随着工作的累积在其周围长出结构化的工作日志。多个 Agent 共享同一份记录：他们在同一条有序日志里发言、交接工作、提出问题，读者改变的是视角而不是位置。本页拥有目标设计。[交互客户端](interactive-clients.md)拥有跨终端与浏览器的共用客户端契约和交付顺序。

## 定位

| 它是 | 它不是 |
|---|---|
| Agent 工作的阅读与操舵界面 | 一个带输入框的聊天产品 |
| 多个 Agent 在其中发言、交接和提问的单一记录 | 指标与图表的仪表盘 |
| 审阅 diff、命令结果和测试报告的地方 | 编辑器或文件浏览器 |
| 任何 Session、Agent 和条目都有可分享地址 | 终端编辑与快捷键深度的替代品 |

浏览器靠读、全局、导航和留痕取得存在理由：长输出、diff、表格和测试报告在这里比终端好读；每个 Agent 都在同一份记录里可见，而不需要为它占一列；每个条目都有稳定地址；标签页可以开着，工作由服务端继续。Session 用量按需查看，不占据页面。这些能力划定范围。仅仅复现终端编辑能力的事情归终端。

## 保留什么，替换什么

界面重写。当前应用的以下性质被保留，因为它们表达的是既定契约而非表现：

- HTTP 与 NDJSON Session 协议，包括命令标识、回执、重放和观察游标。
- 跨 Agent 的 Session 级观察：一条有序流，每个条目都带产生它的 Agent。
- 未确认命令的持久恢复，包括回执查询、仅重放的重提交，以及冲突、缺失、未知三种结果。
- 观察去重：屏障游标、按执行隔离的实时预览、正式条目替换预览。
- 通过统一二进制提供的同源资产、本地交接的 ticket 交换，以及远程服务的显式 token 认证。
- `crates/kuku-server/tests/common/fixtures` 下的共享协议样例，作为跨客户端契约检查。

组件树、状态组织、样式系统和构建配套全部替换。当前应用自带的客户端 lint 与提交钩子被移除，改用仓库级流程。

## 交互模型

### 对话语法，工作台结构

熟悉度是硬要求。一个只用过聊天助手的新用户，不解释也能发出第一条消息，并看懂第一条回复。因此页面保留对话的语法，只替换它的容器：

| 保留 | 不使用 |
|---|---|
| 输入框贴底，Enter 发送，Shift+Enter 换行 | 带尖角的气泡、头像列、左右对置 |
| 发出的消息立即出现在日志下方 | 每条消息一张卡片 |
| 回复就地流式出现，视口跟随 | 打字指示器、装饰性动画 |
| 思考内容在回复上方，默认收起 | 让用户只能被动相信的隐藏信息 |
| 每条消息都写明发言人与收件人 | 按 Agent 分频道或私信线程 |

用户消息落在同一画布上一块有色调的底面上。这块底面是全球通用的“我说话了”信号，识别成本为零，而布局仍然是工作日志而不是气泡流。它的署名行写明收件人，助手正文则完全不放进容器：它按文档排版，因此长回复读起来是一篇文章，而不是困在框里的文字。

结构是渐进的。短的 Session 看起来就是一段干净的对话。随着轮次和工具调用累积，章节头、压缩的工作行和轮次脊柱才出现；新增的每种结构都可收起，跟读一次问答不需要它们中的任何一个。

### 轮次章节

Turn 是工作单位。它的头部带轮次编号、终态和工具调用数，并在正文滚动时保持 pinned。轮次之间由一条连续的竖直脊柱相连，每个轮次是一个节点，这既给出阅读位置，也让长 Session 不需要树状视图就能导航。脊柱是唯一常驻的结构性装饰；默认没有其他容器画边框。

头部从不逐秒计数。活动轮次显示状态和工具数；耗时和 token 用量在轮次结束时结算，因此工作正忙时页面是静止的。统计使用等宽数字，并以元信息对比度出现；字段顺序沿用终端状态栏，让两个客户端教出同一种阅读顺序。

### 工作是压缩，不是卡片

工具调用先被压缩，再按需展开。在房间里，同一 Agent 在同一轮内连续发生的调用折叠成一条工作行：Agent、描述这批工作的一句话、调用数和时长。工作行不是卡片，不占阅读栏宽度，也不带装饰性外壳。并行工作呈现为几条安静的行，而不是几列。

展开工作行才显示紧凑的行：读了什么、跑了什么命令、改了哪个文件、结果是什么。写入和编辑显示路径、有界的 diff 预览和行数增减。失败、运行中和等待授权的调用保持醒目但不高声。在镜头里，同一批调用按顺序逐条出现，因为镜头才是检视过程的地方。

细节放在按需打开的查看面板里：参数、结构化结果、diff、命令事实或保留输出，保留输出按偏移分页读取。一个手势——点击、Enter 或空格——打开和关闭它，打开它从不移动阅读位置。

### 发送

输入区写明目标，并按 Agent 保存草稿。新 Session 的标识和第一条命令的标识在首次发送前生成，因此回执丢失时用同一组标识重试，只会创建一个 Session、投递一次。Enter 对忙碌的 Agent 是插话；显式动作排到下一轮。草稿、未确认发送、排队输入和已接纳输入是同一条消息的四种可区分状态，显示在消息自身而不是单独的日志里。

目标跟随视角：在房间里阅读时保留上一个目标；选中某个 Agent 的镜头时，该 Agent 成为目标。对于不是发给另一个 Agent 的消息，目标从不含糊。

### 注意力与待决工作

所有需要人的工作都在它发生的地方浮现：

- 等待中的提问或授权请求内联出现在房间里，标明提问的 Agent，使用同一种警示处理。参与者条为每个 Agent 带上计数，一眼就能回答谁被卡住。在一个标签页作答，所有地方都结算，其他标签页观察到结果。
- 仍在排队的输入紧贴输入框上方，带投递时机和撤回动作。
- 未确认的命令内联显示在所属消息下方。发送轨迹——发送中、回执、排队、已接纳——用一行小字呈现，不做解释。

因为房间承载了每一个提问，用户不必逐个访问 Agent 去弄清谁在等待。

### 阅读位置

用户位于底部时日志跟随新输出。向上滚动会暂停跟随，并在新条目和预览到达时保持锚点。回到最新的入口贴着输入框，不放在浮动的角落。房间和每个镜头各自保留锚点，每个 Agent 各自保留草稿；切换视角会恢复两者，且绝不发起模型请求。

### 多个 Agent：房间与镜头

Session 是一份记录，Agent 是其中的发言人。每条消息有一条署名行，写明发言人与收件人——`You → Lead`、`Lead → Reviewer`、`Reviewer → you`。Agent 之间的工作是日志里的一等发言，而不是复制的摘要或指向别处的引用行。并行工作按提交顺序交错出现；一个尚未发言的 Agent 的一批工作只是一条安静的工作行，存在感不占一列。

房间是默认视图。它完整显示所有发言，压缩所有工作，并把每个待决事项内联放在它发生的位置。决定在房间里做，因为房间已经容纳了每一个 Agent。

镜头是换视角，不是换目的地。选中一个 Agent，会把同一份记录过滤成该 Agent 的完整日志：它的思考、工具行与结果，以及它收发的消息。其他 Agent 的消息以引用上下文出现，因此镜头读起来是这个 Agent 的一天，而不是一段没头没尾的片段。镜头是同一批条目上的选择器，不是第二份日志，也不是第二个订阅。`Escape` 回到房间。

参与者条替代 Agent 侧栏：先是房间，然后是每个 Agent，带身份色点、名称、当前状态和需要你的计数。左侧栏只属于 Session，因此 Session 和 Agent 从不争抢同一块表面。选择参与者是对视图的导航而非创建：它绝不发起模型请求。

宽屏下并排显示房间与一个镜头可以作为后续增量；它限于两栏，且绝不是默认。面向 Team 的时间对齐泳道仍然不做。

### 布局

一套组件服务所有宽度；变化的只是布局，不是组件。

| 宽度 | 形态 |
|---|---|
| 宽 | Session 侧栏、一条有界的房间或镜头栏，以及覆在页边上的按需抽屉 |
| 中 | 房间或镜头栏；Session 侧栏收起，参与者条留在记录上方；抽屉以浮层出现 |
| 窄 | 单栏；Session 列表和抽屉变为 Sheet；参与者条横向滚动；输入框停在键盘上方 |

任何宽度下都没有 Agent 侧栏。窄屏是设计的一部分而非推迟项：触摸目标、安全区内边距和 visual viewport 从一开始就处理，精致的手机专属手势留到后续阶段。

### 地址

URL 标识正在读什么：工作区、Session，可选一个 Agent 的镜头或一个条目。没有指定视图时默认是房间。打开链接恢复该视图；一个指向失败命令的分享链接和一张截图同样有用。表现偏好——主题、语言、密度、折叠状态——留在本地，绝不进入 URL。

### 找到工作

一个工作区的 Session 以可辨认的标题、最近活动和等待中的 Agent 列在左侧栏，选中即导航而不加载预览。搜索感知语言区域，覆盖标题与首条提示词。没有单独的仪表盘：列表是导航辅助，不是指标界面。

### 按需用量

Session 事实——耗时、输入与输出 token、缓存命中率、缓存读取、工具调用、失败数以及各 Agent 占比——从 Session 头部打开一个抽屉查看。抽屉默认隐藏，以浮层出现而不压缩阅读栏，关闭后回到原锚点。数值来自投影后的轮次事实；缺失的测量标记为缺失，而不是推断。缓存命中率只使用同时报告输入 token 和缓存读取 token 的请求，两项合计使用同一批样本。

## 视觉系统

### 方向

安静、准确、克制。一个画布、一条阅读栏、一条脊柱。记录里唯一有填充的表面是用户自己的消息；唯一使用警示色的对象是待决事项。层级来自字号、字重和空间，而不是阴影或嵌套边框。页面默认是安静的，因此只有等待、失败和成功会跳出来。

两个主题与终端共用同一个色系：冷蓝灰中性色加青绿强调色。亮色主题是冷调米白而非暖纸色，因此两个客户端在任何主题下都像同一个产品。

### 注意力预算

注意力是稀缺资源，因此强调是预算而不是累积。每一屏只有一个焦点对象，其他一切至少退后一级。阅读顺序是固定的：

1. 待决事项。
2. Agent 的回答。
3. 用户的消息。
4. 证据：diff、命令结果、测试报告。
5. 工作与思考。
6. 轮次元信息与外壳。

轮次头、署名行、工具字形和输入区提示停在元信息对比度：需要时读得到，不需要时不抢眼。颜色是状态，不是装饰。强调色标记当前目标或活跃焦点；警示色标记“需要你”；成功和错误只出现在承载该事实的那一行。Agent 身份色只是小色点，且绝不是唯一信号，因为名称始终在场。强调不叠加：待决事项不再同时用强调色，用户消息不再同时加粗，轮次头也不再同时是一张卡片。

### Token 分层

颜色、字体、间距、圆角和动效一次性定义，按角色取用。组件里不出现字面颜色值。

| 层 | 内容 | 消费者 |
|---|---|---|
| 原始层 | 各主题的中性色阶、强调色与状态色 | 仅语义层 |
| 语义层 | `surface`、`surface.user`、`panel`、`text.primary`、`text.muted`、`accent`、`state.running`、`state.waiting`、`state.success`、`state.error`、`agent.identity`、`border.subtle`、`code.background` 等角色 | 所有组件与 story |
| 组件层 | 角色不足以表达时少量组合值，例如带色调的用户底面 | 单一组件族 |

原始层数值由终端调色板派生，因此在这里改动就是改变两个客户端的气质。语义角色名与终端的样式常量一一对应，让两个客户端描述同一组角色而不是各自发明词汇。

Token 以自定义属性形式定义在根元素和主题属性上，并通过工具层的主题指令暴露（目前是 Tailwind 的 `@theme`），因此调整一个值只是改一个文件，所有使用处随之变化。仅开发环境可用的 token 页渲染两个主题的完整色板、字阶和间距刻度，Storybook 用工具栏切换主题。单元测试断言两个主题下每一组“文字置于表面”的对比度，使调值不会悄悄破坏可读性。

### 排版

两个字族：界面与代码。界面用系统栈，显式指定中文与日文后备字体；界面不依赖网络字体。代码用等宽栈，带支持 CJK 的等宽后备字体，使代码围栏里的中文保持对齐。字号是一个短刻度：Agent 正文是页面上最大的文字，用户消息低一级，元信息再低一级，章节标题用字号和字重而不与回答争抢。轮次头使用等宽字体，因此读起来是仪表而不是内容。宽屏下正文保持有界的行宽。

### 动效

只有两个动画：流式光标和阶段指示。状态变化用淡入。时长很短，缓动为线性或接近线性，减少动态偏好会移除位移而保留状态可辨识。

布局的稳定靠构造而不是靠动画。输入框向上生长而不挤动日志，工作行在状态变化时保持高度，轮次头为结算后的元信息预留空间，统计使用等宽数字。没有任何东西在逐秒走动：耗时只在轮次结算时变化。平滑感主要来自没有移动。

## 国际化

界面提供英文与简体中文，结构上为更多语言做好准备。

- 消息在构建期从源码抽取；缺失翻译会让构建失败，而不是静默回退。
- 日期、数字、时长和排序全部经由国际化库，不用字符串拼接。Session 搜索使用感知语言区域的排序。
- 服务端错误按 code 本地化。客户端把已知 code 映射到目录中的文案，未知的回落为服务端文本，因此新的服务端错误在翻译之前就是可读的。
- 用户与模型的内容绝不翻译。Agent 名称与地址是用户数据，保持原样。日志正文、路径、diff 和代码带自动方向，代码块保持从左到右。
- 排版相应调整：CJK 使用更高行高，标题不加字间距、不转大写，宽度随内容而不是固定。

语言是本地偏好，不进入 URL。

## 架构

### 分层

```
SDK 事实层      CommandExecutionFacts、FileMutationFacts、TurnSummary、AgentProgress
Server 投影层   有类型的 Session 条目：每个事件是什么、谁产生、发给谁
客户端视图层    每个客户端在每个视口与偏好下显示什么
```

边界是规则而不是偏好。当两个客户端会从同一批事实算出同一答案，且答案需要工具或 SDK 语义时，推导属于服务端：配对工具调用与结果、给工具分类、计算 diff 摘要、轮次编号、轮次统计、保留输出引用、消息收件人。当推导依赖视口、时间、交互或偏好时，它属于客户端：合并阈值、折叠状态、房间的压缩、镜头过滤、滚动锚点、计时器与阶段防抖、数字样式、断点。

客户端不共享视图层。终端的视图层产出面向单元格缓冲的定宽文本行，浏览器用不上；值得共享的是语义，而语义属于投影层。

### Server 投影契约

当前投影由服务端 wire 层的手写 JSON 构成，两个客户端都按字符串键读取。这是既有漂移的来源：服务端发 `reasoning_preview`，浏览器读 `thinking`；实时的 `thinking` 事件不带内容；轮次统计、后台任务完成和轮次编号有发出但无人使用。第一阶段把它换成有类型的契约：

- 每个条目变体一个 Rust 类型，按 tagged enum 序列化，覆盖用户、助手、思考、工具调用与结果、提问、授权、答复、后台任务完成、轮次统计、状态与错误。
- 每个条目携带产生它的 Agent。消息携带发言人和收件人，收件人是 `you` 或一个 Agent 地址；Agent 之间的投递保留发送者和接收会话，因此房间不需要猜测就能渲染署名行。
- Session 级观察是房间的来源：一条跨 Agent 的有序流。镜头是客户端在这批条目上的选择器，不是单独的订阅。
- 工具条目携带分类、生命周期状态，以及客户端默认渲染所需的结构化事实，包括 diff、命令事实、测试报告和保留输出引用。
- 实时事件携带类型、负载、思考文本和发言人，因此流式正文会以正确的署名落进房间。
- 每条历史与实时条目在可知时携带轮次编号与轮次统计。轮次统计携带耗时、工具数、输入、输出和缓存读取 token，因此用量由投影事实聚合。
- 错误携带来自已记录目录的稳定 code。
- TypeScript 类型从这些 Rust 类型生成。浏览器不再保留手写协议类型。
- 共享协议样例由有类型契约重新生成，继续作为跨客户端检查。

终端客户端在同一次改动中迁移到同一批类型，因此契约从一开始就有两个真实消费者。

### 客户端状态

Session 视图是一个纯 reducer：`(state, frame) → state`，其中 frame 是快照、历史页、已提交条目、实时事件或连接转换。它为 Session 保存一条有序日志，而不是为每个 Agent 各存一份，因此房间流和每个镜头共享同一个来源。它独立于 React、确定、可回放，因此通过回放录制的流和共享样例测试，而不是通过渲染测试。

焦点——房间或某个 Agent——是视图状态。镜头是一个选择器：把涉及该 Agent 的条目视为本体，把其他 Agent 的条目视为引用上下文。各视图的滚动锚点和各 Agent 的草稿也留在本地，都不写回服务端。

React 通过外部 store 订阅。请求—响应型资源——Session 列表、模型目录、Skill、路径补全、服务状态——使用查询层，带缓存与取消。持久命令状态保持为独立 store，因为它要跨导航和刷新存活。

布局、折叠、主题和语言偏好是本地且按客户端保存的。

### 流式与渲染

Markdown 增量解析：已闭合的块只渲染一次并缓存，只有尾部块随文字到达重新解析。代码高亮按语言加载，退化时按纯文本显示。流式正文携带其发言人并按顺序追加；如果读者在另一个视图里，参与者条显示活动，而不是抢走滚动位置。长日志虚拟化，使用稳定的测量高度和锚定滚动。收起的工具行只测量一次，展开它不会移动上方的锚点。保留输出按偏移取回并追加，绝不整段重读。

### 资产与打包

构建产物嵌入统一二进制，与 API 同源提供。未嵌入资产源码构建保持现有回退行为。开发服务器把 API 代理到显式本地服务，并打印它代理到的地址。构建从 lockfile 可复现，体积预算纳入发布检查，因为高亮语法和字体才是增长的部分。

## 无障碍

- 完整键盘操作：房间与镜头导航、参与者切换、决策面板和输入区，配一套有文档的快捷键。`Escape` 从镜头回到房间。
- 处处可见焦点；没有焦点陷阱；查看面板关闭后焦点回到来源。
- 语义地标，并为新的已提交条目和要紧的状态变化设置 live region；流式文本以礼方式播报并限流；需要你的计数变化时播报。
- 署名行里的名称是可访问名称的按钮，参与者条暴露所选视图和需要你的计数，而不是只靠颜色。
- 两个主题的对比度由测试强制。
- 尊重减少动态偏好。

## 交付阶段

每个阶段是一个可审查的结果，各带验收条件。共享同一次改动时可以合并。

### 阶段 0 — 有类型的 Session 契约

把服务端投影类型化，生成浏览器类型，迁移终端客户端，重新生成共享样例。契约包含每个条目的产生 Agent、消息的发言人与收件人、Session 级有序观察，以及轮次统计上的用量字段。验收：两个客户端都针对生成的类型构建；共享样例覆盖每个条目变体，包括一条 Agent 之间的消息；回放录制的多 Agent 流进 reducer，得到正确的房间署名行与镜头成员；浏览器从已提交数据渲染思考、轮次统计和后台任务完成。

### 阶段 1 — 外壳与阅读

替换应用外壳：布局、主题与 token 系统（含 token 页与对比度测试）、国际化基础设施、连接门与 ticket 交接、Session 侧栏、参与者条、房间与镜头、深链接、轮次章节、可展开的压缩工作行，以及支持分页输出的查看面板。验收：一段包含长输出、混合工具结果、跨 Agent 交接和中文内容的录制多 Agent Session，在宽、中、窄三种宽度下正确渲染；每个条目可寻址；镜头把收到的消息显示为引用上下文，并把自己的工作按顺序显示；切换视图保留锚点与草稿且不发起请求；键盘与读屏检查通过文档化的用例集。

### 阶段 2 — 写作与决策

输入区带目标选择与按 Agent 的草稿持久化、时机选择、排队输入列表与撤回、发送轨迹、未确认命令恢复、内联的提问与授权请求及参与者计数、打断与继续。验收：共享命令场景在浏览器中通过，包括回执丢失、刷新恢复、第二个标签页先作答，以及撤回与接纳竞争；在房间里作答的提问，在提问者的镜头和所有标签页中一并结算。

### 阶段 3 — 广度

模型与思考设置（含等待生效状态）、Skill 与路径补全、后台任务、命名值、服务状态与重启引导、Session 删除与搜索。验收：每个界面有录制流回放检查和一条键盘路径。

### 阶段 4 — 审阅与用量

Session 级别、只读的文件变更审阅，带提交状态，由服务端聚合；以及按需打开的用量抽屉：耗时、token、缓存命中率、缓存读取、工具调用、失败数和各 Agent 占比。验收：聚合字段写入服务端参考文档；两个界面只读取投影事实，默认关闭，关闭后把焦点和滚动还给来源。

## 验证

- 协议：共享样例与录制的真实流回放进 reducer，断言房间顺序、署名行、收件人、镜头成员和推导出的视图状态，而不是像素。
- 表现：Storybook story 由录制的流构建，因此组件浏览器和回归来源是同一批产物；视觉快照覆盖房间与一个镜头、两个主题和三种宽度。
- 行为：共享的命令、观察与恢复场景针对真实服务端和可控 provider 运行，见[交互客户端](interactive-clients.md#开发时如何测试)。一次两个 Agent 的交接从房间作答、在提问者的镜头中查看、刷新，再在终端继续。
- 交付：安装后的二进制通过既有验收入口检查，包括浏览器交接，以及从终端开始、在浏览器继续的一次会话。
