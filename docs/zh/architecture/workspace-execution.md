# 工作区执行与会话变量

## 产品承诺

kuku 应让模型能在原生 Windows 上完成真实工程任务，用户无需安装 Python、Node.js、Git Bash，也无需模型熟练编写 PowerShell。Linux 和 macOS 同等重要。Rust SDK 保持精简并可独立使用。空闲 Agent、普通对话、单次文件操作不应产生脚本 worker 开销。大型任务结束后，内存应回落到接近空闲基线。在资源紧张和配置充足的执行设备上分别测量。

用户、模型和 SDK 调用者应对任务意图、实际动作和结果有一致理解。工具要同时交付对模型有用的证据和宿主可解析的事实。TUI 据此显示摘要和详情，后续客户端复用同一个 SDK 契约。现有内部 API 或演示客户端妨碍这些目标时，可以直接重写。

## 建议的执行入口

将固定版本的 QuickJS 嵌入分发的 kuku 二进制，按需启动 worker。输入为支持顶层 `await` 的 JS 函数体，以返回值交付结果。变量、模板字符串、循环、条件、JSON 和 Promise 沿用标准 JS。展示当前可用的宿主方法及其真实签名。同一工作区脚本应能在三端默认安装上运行。Python 的优势包括模型熟悉的标准库，例如带引号、跨行的 CSV 解析。反复出现此类任务时，应提供小而正确的解析能力。捆绑 Python 发行版、模拟 Node 以及全局字符串模板替换，对这个场景代价较大。

| 任务 | 建议入口与职责 |
|---|---|
| 查看、搜索或精确修改一个文件 | 保留简短直接工具。脚本可以组合相同的已授权动作。语义相同的动作沿用同一名称和一份 Rust 实现。行号与装饰由展示层添加。 |
| 有依赖或批量的工作区操作 | 一次脚本可以查找、搜索、读取、编辑、写入、查询状态和删除文件。中间数据留在本地。示例要完整展示读取、计算、交付。格式未知时先检查，规则明确时一次完成。 |
| 调用已安装的程序 | 模型使用 `run_command({program, args?, cwd?, background?, title?})`。按字面传递参数。省略 `cwd` 时使用 Agent 工作区。顶层调用的 `title` 向用户说明命令或脚本的目的。直接工具和 `run_js` 共用 Rust 进程执行器。嵌入宿主可以设置进程截止时间。两种调用的说明和传入不受支持的 `timeout` 参数时的错误回执都应说明截止时间由谁控制。 |
| 执行 Shell 脚本或使用 Shell 语法 | 用字面参数显式启动所需解释器。嵌入宿主可选择有类型的 Shell 调用。按实际调用授权和记录，包括解释器与工作目录。 |
| 委派、提问或等待回复 | Session 持有可恢复回执、身份和等待。子 Agent 能在所获授权内运行脚本，无工具子 Agent 只能回复。可考虑在创建时传首条任务，与长期角色指令分别表达。等待指定 Agent 的结果应取代模型反复轮询。 |

其余工具保留可发现的直接入口。真实任务受益于组合操作时再向 JS 开放扩展。通用字符串工具调度器和重复描述每个宿主工具，都会增加模型的选择负担。经过验证、将反复使用的流程可以保存为普通项目脚本。

## 宿主事实与模型证据

从现有[模块契约](module-contracts.md)和[保留输出](../reference/tools.md)出发，在公开 SDK 中明确共同的执行结果、动作身份和输出引用。动作专属事实应有类型，例如退出状态、实际观察到的文件变更，以及测试程序报告的结果。明确输出完整性、部分完成和状态未知。原生工具与脚本共用授权、执行和记录边界。TUI 根据宿主观察到的事实渲染卡片和详情。任意外部程序可能产生宿主无法识别的其他影响。

识别出测试报告时，可以返回统计、首个失败用例、有界原文和引用。格式陌生时，返回退出状态和有用的原文片段。脚本成功返回不能证明测试通过。让模型看到足以做下一步判断的有界证据。宿主处理结果无需解析模型自然语言。已进入模型上下文的精确视图保持稳定。

执行者提供文件全文并收到写入成功的确认后，就掌握了这个版本。再次编辑或覆盖相同版本时，无需把刚写入的内容重新读一遍。这份依据只属于写入者，且必须仍在其有效历史中。局部编辑可使用调用方提供的原文，只要它在当前文件中恰好匹配一处。若有重复，当前版本的局部读取可以区分对应位置。对要求掌握整文件的操作，局部读取或编辑只能证明已观察的范围。确定性脚本可以转换完整读取的文件，无需把全文送给模型。宿主在派发时仍须校验授权和文件当前版本。

顶层命令或工作区脚本只启动一次。前台调用默认观察十秒，显式后台调用观察一秒。窗口结束时仍在执行的调用返回 Job 句柄。转入后台沿用同一执行和保留输出。`wait_job` 可用时，模型看到的运行回执会附上具体调用，用于下一步依赖此 Job 最终结果的情况。仅经过等待窗口不触发模型推理；新输入可在执行期间引导 Agent。脚本内 await 的命令始终得到最终结构化结果。宿主 I/O 等待与 JavaScript 运算预算分别处理。所属 Session 提供查看和取消，并投递一次完成结果。

同一条模型响应中的工作区读取可以并发。工作区写入、任意程序和脚本与读取及其他写入之间按调用顺序派发。前序写入仍在等待时，排在后面的读取也等待。在授权和容量允许时，工作区之外的调用可以独立继续。命令或脚本返回 Job 句柄后，调用方可以在 Job 运行期间继续工作。每次调用保留独立的结果与授权。

接纳任何工具调用之前，先校验完整调用批次。完整的模型响应声明调用工具但参数 JSON 无效时，Session 可按[运行时重试策略](../reference/sdk.md#限额与用量)重新生成当前步骤。被拒绝的响应不进入后续模型输入。记录失败原因和恢复情况，让用户能区分响应无效与工具执行失败。

## 命令输出处理提案

直接工具、JavaScript 和 Job 共用一条执行路径。工具目录与 Prompt 说明如何选择工具。执行器准备并授权最终调用。输出采集器管理 stdout、stderr、配额及保留引用。Rust 从捕获结果提取证据。模型收到有界视图，客户端使用同一份结构化事实和输出引用，上下文接纳记录实际发送的视图。

短输出能装进模型预览预算时直接返回原文。短输出的起始上限取 2 KiB 和 40 行，再用真实工作负载校准。长输出提供有用的证据、观察到的数据形态和保留引用。标明形态来自开头的样本还是已验证的格式。展示代表性字段或列名，并依据 Agent 实际可用的方法简短提示如何提取。失败时优先给诊断留出空间。分别标明进程结果、捕获完整性和呈现限制。前台结果和自动 Job 投递使用同一套呈现策略。

对于原本需要多次模型 Step，或会将中间数据带进模型上下文的确定性处理，默认 Prompt 优先引导使用 `run_js`。示例采用已开放的方法和实际返回字段。一次文件操作走对应的直接工具，调用程序走原生执行。验收统计适合脚本组合的任务里模型如何选工具、能否一次写对，以及总模型请求数。

`read_output` 负责按范围读原始输出。为 JS 增加对同一份已授权捕获的字面文本搜索，首个入口为 `tools.search_output`。Rust 用有界内存扫描并检查取消。返回少量匹配项、流标识、原始字节偏移、续读位置和捕获完整性。任务需要自定义逻辑时，在本地脚本里处理中间数据。TUI 和模型可以各自读取同一范围。

### 内置命令规则格式

逐行过滤采用 RTK TOML 规则的明确子集。沿用 `[filters.<name>]`、`description`、`match_command`、`strip_ansi`、互斥的 `strip_lines_matching` 和 `keep_lines_matching`、`head_lines`、`tail_lines`、`max_lines` 及 `[[tests.<name>]]`。这些字段按 RTK 的顺序处理。规则只编译一次，遇到未支持字段时返回诊断。借鉴规则和夹具时记录对应的上游提交。 [RTK 规则与执行顺序](https://github.com/rtk-ai/rtk/blob/b8cb15167268b7a27519b84f79e53c4cb742bafe/src/core/toml_filter.rs#L600)

按准备好的原生程序与参数边界选规则。`match_command` 在该调用的确定性文本表示上匹配，仅用于选择输出规则。输出模式和 reporter 也参与匹配。执行已授权的程序和参数。匹配存在歧义或捕获格式缺少已验证规则时，使用通用预览。

用 TOML 处理可预测的噪声行，用 Rust 解析多行诊断和测试报告。扩展现有流式报告收集器，统一构建输出视图。视图记录类型和选中的规则身份，进程结果仍是权威依据。摘要明确标识，可操作证据带原始范围。只有实际保留的字节才记录范围，stdout 和 stderr 交错时保留流标识。格式化失败、缺失关键证据或扩大结果时，回到通用视图。

| 首版规则族 | 保留的证据 |
|---|---|
| `cargo build`、`cargo check`、`cargo clippy` | 结果、诊断块、源码位置和警告 |
| `cargo test` | 测试套件统计、失败用例和相关断言 |
| `pytest` | 实际报告的结果统计、失败名称和位置 |
| `go test` | 相关包、失败测试和关键诊断片段 |
| `tsc` | 源码位置、错误码和诊断消息 |
| `vitest`、`jest` | 已识别 reporter 的套件统计、失败用例和相关断言 |
| `npm install`、`npm ci`、`pnpm install` | 依赖解析与生命周期错误、依赖冲突和安全警告 |
| `git status` | 已识别长输出中的文件状态分组和冲突 |

每类规则基于实际捕获格式。RTK 规则有时依赖额外的参数或另一种 reporter，借鉴时连同夹具验证相同模式，之后再启用。正文就是用户所需证据的输出，例如 diff 或搜索结果，使用通用预览和原文范围读取。

### 交付顺序

1. 稳定原生命令接口和通用预览，在同一公开执行流程里覆盖后台一秒观察及结果投递。
2. 通过现有保留输出读取器和 JS 宿主边界提供 Rust 字面搜索。
3. 用完整的 Cargo 路径落地共享规则格式，覆盖诊断、来源范围和重放测试。其余规则族分批独立验证，再宣布首版覆盖范围。
4. 通过 SDK、已安装 TUI 和代表性任务对比完整候选版本与通用预览基线。用记录下来的证据选择下一项优化。 [命令输出验收](../contributing/testing.md#命令输出与长任务验收)

## 输出与命名数据

直接文件工具和 JavaScript 宿主动作共用有界读取。搜索在读取过程中校验 UTF-8，并根据正则必须包含的字面量定位候选行。文件通过一致性校验后，才接纳它的命中。工作区操作的容量许可在底层工作取消或正常结算后释放。I/O 额度由 [RuntimeLimits](../reference/sdk.md#限额与用量) 配置，共享执行容量由宿主管理。

浏览目录时默认列出直接子项。用文件 glob 或显式深度搜索下级目录。小列表完整返回，长列表在同一预算内说明范围、总数和缩小查询的方法。原生调用与脚本共用这个行为。见[工具参考](../reference/tools.md)。

直接工具和 JS 共用一个有界读取器。脚本可以按行迭代或按字节块读取，保留流身份、实际偏移、解码边界、原始字节和截断状态。JSON 和正则使用 JS 原生能力；跨行 CSV 需要记录级解析器。小型结构化结果可直接返回。大型派生数据流式写进新的 Session output，内容保存后才交付引用。原始日志可以独立读取。用户要求交付报告时再写到工作区。

URL 下载返回 Session 输出引用，原 Agent 可以通过输出读取器查看内容。用户明确要求保存文件时，再将下载内容写入项目目录。

图像查看使用所选模型和协议原生的工具结果图像能力。授权规范化的工作区路径，并在 Session 输出存储中保存有界快照。Context 纳入图像类型和不可变引用。构建请求时，在剩余请求字节预算内加载当前轮和上一轮的图像，由适配器按相应协议发送。更早的结果只提供文本。近期快照受保留保护，更早的快照按常规期限过期。验收覆盖工作区文件变动后的回放、关闭后重开，以及受保护路径和授权拒绝在读取前生效。见[工具参考](../reference/tools.md)。

| 数据 | 生命周期与可见性 |
|---|---|
| 脚本局部变量、函数、Promise | 限于本次调用，释放 worker 时释放其堆。 |
| 普通工具输出 | 每次执行有可追溯回执和有界保留期。模型不必提前猜该命名哪份日志，也能比较最近两次构建。正文已经回收时应明确告知，保留执行结果。 |
| 显式命名的会话变量 | 用可读名称绑定具体值或已有 output。跨 Turn、断连、关闭和重开持久化。先加载元信息，按需取正文。默认对所属 Agent 可见，可显式向其他 Agent 分享选定引用。 |
| 工作区交付物 | 生命周期独立的普通用户文件。同一工作区可以有多份彼此独立的 Session。 |

用户可以在长粘贴、附件**进入模型上下文之前**命名。模型保存已识别结果时只需给出名称和来源，无需复制原文。TUI 中点选或输入变量引用时，将确定的引用随请求传递。按需查询有关名称，拼错名称不能静默绑定到相似值。重复保存同一来源应幂等。同名换来源需要明确更新。新内容保存成功后才切换绑定；已经派发的动作和已委派输入继续引用原先的值。实时路径与已保存基线分别表达。

对每个 Session 限制命名数量和总保留字节。给已有输出命名不再复制数据。普通输出在承诺的保留期结束，且没有命名值、在途动作或交接引用依赖时可回收。空间不足时保住已有基线并报告更新失败或捕获截断。删除 Session 保留用户工作区文件。项目级变量、持久 JS 堆和独立产物平台尚无首段交付需求。

凭据别名仅用于减少重复粘贴和意外展示。优先复用已有配置，不在示例中使用密钥，不把别名展开进 Prompt 或持久工具参数。给外部程序提供凭据，意味着该程序能接触真值。本方案不建设通用密钥管理器，也不承诺额外隔离。

## 调度、中断与资源归属

给模型的工具预览和分页保持有界，正文按宿主的单份捕获和总磁盘预算流式写入 Session 存储。预算耗尽或写盘失败时，由遇到问题的操作明确报告。模型生成长度单独配置。

宿主 I/O 真正异步。独立读取可用 `Promise.all`，依赖前序结果的编辑按顺序 `await`，需要收集部分成功时可用 `Promise.allSettled`。大输入分批处理，避免 JS 堆保留所有文件。限制堆、栈、执行耗时、宿主缓冲、排队和活跃操作数、捕获字节及保留空间。并发额度由同一**执行宿主**上的 Agent 共享。手机连接桌面服务时，手机影响布局和渲染，执行额度取决于桌面。先用可配置限额，以实测决定是否自适应或保留热 worker。

每个副作用派发前检查真实 Agent、动作、最终参数和目标。程序能越过文件工具控制修改文件，因此执行程序需要独立权限。复用进程树清理和输出捕获。中断时停止新派发，收束已有工作并返回完成项。新输入在安全边界生效。数量可确定时，TUI 可以显示“已停止 · 已修改 12/40 个文件”。

待批准动作可以保存已准备参数、内容引用、版本条件和回执。等待时宿主可释放 worker。批准后只重新校验并执行匹配动作一次，把结果交给 Agent 继续推进。已释放的 VM 无法从任意 JS 调用栈续跑。中断或重开后，副作用未知的程序不能静默重跑。持久等待与恢复遵循[核心方向](core-direction.md)。

长任务通过已有的工具与 Job 边界提供执行用时和观察到的进展。进程截止时间与观察窗口分别处理，用单调时钟计算经过的时间。安静多久只能说明多久没有观察到输出。终止依据可以是明确的截止时间、已经确定的结果或具体阻碍。及时投递终态，并允许独立工作继续。进展与 Agent 即将处理的工作一并接纳。模型推理由有用的证据或显式输入触发。

## 采纳方案所需证据

实现选型仍是提案。独立 Windows 原生嵌入试验证明静态链接的小型宿主可以在没有 Node、Python 时执行源码。其 EXE 体积不等于 kuku 发行包体积增量或常驻内存。五次显式 low 思考档、每次只给一个工具的 DeepSeek Flash 请求，探索了脚本熟悉度和宿主接口误用。它不能验证工具选择、模型总体优劣或端到端完成能力。原工作树的本地证据目录为 `benchmarks/acceptance/windows-js-capability/`。

1. 经公开 SDK 和已安装 TUI 打通完整路径。运行本机程序、用 JS 分析保留输出、交付结构化事实和有界模型证据，重开 Session 后继续使用命名结果。
2. 在原生 Windows、Linux 和 macOS 验证相同输入产物、Unicode 及含空格／引号／& 的字面参数、缺失程序、平台解释器、编码、超时、取消和清理。覆盖没有额外脚本运行时的 Windows。
3. 给模型**完整的实际可用工具集**，以 DeepSeek Flash high 为主验收，低档检查易用性。比较单次精确编辑和大日志分析时的直接工具与脚本路径。测正确性、调用数、上下文字节、token 和耗时。覆盖歧义来源、重复命名、找不到引用和首个动作失败后的恢复。
4. 在资源紧张与普通设备测空闲增量内存和 CPU、冷启动、峰值内存、磁盘增长以及任务后的内存回落。反复构建，仅保留一份基线，重开并核对工作区干净。覆盖授权中断、部分写入、子 Agent 交接无轮询以及在途任务重新连接。

数值限额、公开类型名称、首版 JS 方法清单、worker 复用和更多扩展入口由以上证据决定。脚本胶水留在核心 Session 状态机之外。设计评审、实现与前序交互客户端分支的验收分别推进。
