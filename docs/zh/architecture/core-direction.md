# 核心方向 — 先读这一页

## 状态与阅读约定

本页是重写的唯一精简目标，不表示已经交付。现有指南和代码描述当前版本。

核心工作先读本页，再按任务读取相关代码和[演进说明](evolution.md)。本页保持在 100 行以内；替换被推翻的结论，不追加讨论流水账。英文是规范源，中文结构同步。批准文档不等于启动实现。

## 产品与设计判断

kuku 是**附带可用默认 Harness、可嵌入、文件原生的 Rust Agent SDK**。小而完整的执行运行时支撑交互工作、独立子 Agent、Team 和事件驱动的长期工作。CLI、server、UI 使用同一公开 SDK；嵌入不要求 daemon、HTTP server、子进程 CLI 或插件容器。

可靠性、低占用和人类／模型的低认知成本同等重要。每项机制都需要具体用途和唯一责任方。默认 Harness 提供工作提示、工具、模型选择和委派，调用者不必自行组装 Agent 平台。自定义 Harness 通过明确的 SDK 操作选择接收者、上下文、调度和工作完成条件，不替换持久化、授权或执行。

## 保留 kuku 的优点

- **行为 Prompt 保留在可版本化的资源／模板中**，不散落在 Rust 执行分支或工具实现里。结构化运行事实本身不是 Prompt 模板。
- **Prompt 渲染、上下文装配与 provider 适配保持分离。** 资源负责措辞；上下文负责选择、排序及来源记录；provider 声明模型能力并转换准备好的请求。持久记录实际进入模型上下文的内容。
- 保留原生 Skill、可配置的 Preset/Tier、文件事实、可观察装配、有效的 provider／工具实现及相关测试。重写耦合的所有权与执行路径；现有 [Prompt Assembly](prompt-assembly.md) 是参考证据，不要求保留其重放算法。

## 持久对象与执行记录

| 概念 | 目标含义 |
|---|---|
| Session | 一组 Agent 的持久历史和执行事实；是打开、恢复、资源归属和数据保留的单位 |
| Agent | Session 内的稳定地址，拥有自己的上下文、当前配置、待处理输入和可恢复执行状态 |
| Turn | 一个 Agent 接纳工作后的执行轮次记录；Turn 结束不代表业务任务成功 |
| Step | 一次逻辑模型请求及其响应触发的工具调用 |
| ToolCall | 一个动作，可区分请求、授权、派发和结果事实 |
| Job | 已有后台执行及其输出的句柄，不是另一套执行器或结果副本 |

Session 和 Agent 是核心持久对象。使用 **Session 内唯一且不转交给其他 Agent 的扁平、可读地址**，例如 `main`、`reviewer`、`agent-3`。标题可变；挂起、重开和后续工作保持同一身份。人类、模型工具和运行时共用此地址；跨 Session 引用增加 Session 身份。不增加平行的隐藏 Agent UUID／别名体系。示例拼写不是冻结的 API 名称。

创建关系单独记录。默认主 Agent 不天然拥有其他 Agent 的全部管理权；创建祖先关系不等于任务归属、通信权限或资源生命周期。子 Agent 通常留在同一个 Session。独立 Agent 可在获准时互通；父 Turn 结束不取消后代。任务板、Team 成员／角色和长期助理身份属于 Harness。工作可以跨 Agent／Session；支持外部关联，不要求普通 SDK 调用先创建 Task 对象。

## 一条执行路径

- 创建 Agent 和提交输入支持调用者幂等标识：同一命令重试返回原持久回执，冲突复用被拒绝。回执、模型接纳和执行完成是不同事实。输入携带真实来源、目标和关联；看到上下文不增加权限。
- 投递、接纳与激活分开。默认发送唤醒空闲接收者；自定义 Harness 可只入箱，随后控制推进。运行中的 Agent 仅在安全边界接纳输入。保留待处理输入，批量接纳并合并唤醒。明确停止后需要授权续派。
- 每个 Agent 最多有一条正在推进的执行链，不同 Agent 可以并发。Session writer 只串行提交；模型／工具 I/O 不占用 writer。Inbox 和状态是已提交日志的派生视图。运行时回执和路由不依赖模型闲聊确认，也不逐条调用模型分类消息。
- 每个 Step 只准备一次，绑定已接纳输入、有效模型／设置、工具定义和上下文。技术性重试由唯一责任层复用准备结果。后来的输入／配置留到后续边界；过期回调不能修改替代它的新执行。
- 一次模型响应中的工具调用作为批次接收。独立工作并发，冲突工作安全排序，授权绑定最终参数与实际工具定义，保持调用／结果配对并报告部分失败。
- 运行时独立于观察者推进。通过同一公开 SDK 提供提交、配置、明确推进／控制、查询和可续接观察。订阅者断开或变慢不能丢失已提交结果，也不能造成无限缓冲。

## 模型选择与独立上下文

支持 **OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages** 三种独立线路协议，共用同一运行时。每种协议都必须覆盖核心的流式输出、工具使用和多轮执行路径。按实际配置的端点／模型确定能力；协议相同不代表思考、缓存、服务选项或服务端状态相同。协议编解码、连接认证与模型能力保持分离。供应商特有处理留在 provider 边界，不增加另一套执行器，也不改变核心上下文模型。

SDK、用户界面、主 Agent 和子 Agent 使用同一配置解析入口。Preset 定义行为／工具／初始默认值，Tier 提供可复用的模型路由／设置默认值。选择明确配置的连接和模型，不按协议寻找第一条匹配连接。显式 Agent 选择覆盖默认值，不修改其他 Agent 或进程级默认配置。

适配器描述并校验可用的思考和服务选项。两者独立：启用支持的加速不隐式改变模型或思考设置，不强设通用的 `fast/ultrafast` 等级。显式选择不受支持时明确报错。记录请求设置、实际发送的有效设置，以及可获得的 provider 回报；未获确认的内容保持未知。

新 Agent 默认拥有**独立上下文**，不 fork 父 Agent 的对话历史。Harness 明确选择任务材料和引用。复用 Agent 可以保留它自己的积累。资源默认值不代表继承上下文；切换路由不能静默携带不兼容的供应商特有设置。

## 持久事实与缓存连续性

- **已提交文件是权威，内存只是可丢弃加速。** 从一个追加 Session 日志、一个 writer 和独立大输出文件开始。有界流式恢复、增量追加，不每次写入扫描历史。小型可重建索引可服务身份、幂等和查询；检查点与物理分段按实测需求增加。
- 在确认输入、派发副作用和确认结果之前明确持久化屏障。确认输出引用前先保存其内容。恢复重建事实，不恢复挂起的异步调用栈。未知副作用不自动重做；持久化失败停止依赖工作。记录必要事实，不记录每次内部状态变化。
- 工具输出采用有界缓冲和明确配额流式写入。首次进入模型时使用规则化结构摘要或有界回退结果，附读取引用并明确过滤／不完整状态，保留该精确视图。短调用和 Job 共用执行／输出；后续 Job 完成不是原 ToolCall 的第二份结果。不隐式改写命令，不使用全局 shell hook 或默认摘要 LLM。
- 一个有界输出读取入口支持摘要／范围／搜索／增量，UI 查看不消耗模型输出。按承诺生命周期保留引用，不依赖系统临时文件过期。不要引入通用 Artifact 平台。
- **同一上下文段内，已提交的 provider 可见前缀不可变。** 已接纳内容保存一次再引用，不每个 Step 复制完整历史。不用今天的模板／配置／文件重渲历史，不回头剪枝已接纳结果。容量或不兼容变更使用已提交的后继段和交接记录。缓存复用继续是一等目标，但不以此强制 Agent 共享历史，也不承诺 provider 永久保留缓存。

## 等待与资源生命周期

在明确安全边界表达可恢复等待，包括提问或派发前授权。持久记录待决请求、目标动作和回复关联，释放不再需要的执行容量。恢复时只处理匹配且仍有效的请求，并校验当前条件。不把无关消息当成批准，不透明续跑任意执行中的进程。

区分等待、取消当前执行和关闭运行资源。取消停止新派发并清理所属工作；异步关闭等待清理和持久写入，报告失败。重开恢复待处理事实，由 Harness 明确调度。定时器、外部事件接入、跨 Session 助理路由和对外投递策略属于 Harness／宿主。

分别约束模型请求、工具进程、Inbox 接纳、输出和观察队列。休眠 Agent 不需要轮询模型、专属操作系统线程／进程或常驻完整历史副本。共享不可变资源和适用的客户端，只保留需要的活动上下文。等待用户不占模型执行名额。本地内存／I/O、考虑缓存的模型费用和用户可见延迟分别衡量。

## 工作目录、信任与范围

工作目录是普通目录。Agent 默认共享它，调用者可指定其他目录。有无 Git 时核心行为相同。worktree、提交和合并保持显式选择；文件冲突检查依据观察到的内容／版本。SDK 不接管进程 cwd、环境变量、信号、全局日志或无关进程。

定位可信调用者／单用户 SDK；需要强操作系统隔离时由宿主提供。默认本地入口明确采用可信本地策略，嵌入宿主可提供自己的策略。宿主授权边界接收真实调用者、最终动作／参数和目录，允许、拒绝或延后决定。报错／取消不构成授权。不强制规则 DSL、角色层级、审批平台或模型安全分类器。

不从一切皆插件、loop 热替换、通用事件中间件、多存储后端、分布式 writer、内建 Team／任务平台或 workflow DSL 开始。WebUI 重写仍弃用。参考系统为具体契约提供证据，不是要照搬的包结构或产品。

## 交付与工程选择

旧版只有用户本人使用，没有继续维护义务。**不要求旧 API、旧地址或旧 Session 格式兼容层。** 保留有效代码和数据；这不授权删除用户文件。分阶段范围与验收条件维护在[演进说明](evolution.md#交付计划公开-sdk-执行闭环)。

先通过公开 SDK 和薄 CLI 交付真实单 Agent 工作，随后尽早验证使用不同 provider 的独立 Agent，再交付持久等待和小型外部编排示例。选择少量成熟 benchmark case，复用原判定器并配合针对性契约测试。不建设评测平台，不在有用执行之前增加架构证明阶段。

**开发工作流与运行时一起重构。** 全新编码会话应能在不依赖旧聊天的情况下接手范围明确的任务、复现验证、报告证据并留下可靠交接。进度不混入架构正文，私有工作记录保持私有，跟踪与测试工具保持轻量。[开发指南](../contributing/development.md)维护这一工作流；它不成为运行时依赖。

所有权、身份、接纳、配置作用域、持久副作用和资源限制是目标承诺。具体 Rust 签名、事件 schema、数值限额、解析器、所选 case 和检查点方案属于其内的工程选择。证据要求改变承诺时明确修改本页，不根据某个参考实现自行改向。
