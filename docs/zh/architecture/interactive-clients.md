# 交互客户端重构计划 — server、Rust TUI 与 WebUI

交付目标是让开发者用安装好的 `kuku` 完成一整次开发任务。在项目目录打开终端，配好模型，发送任务，查看工具结果，回答问题，给忙碌的 Agent 插话，再换一个终端或浏览器接着工作。工具运行期间安装新客户端，原 server 仍能完成这次工作。下面的阶段规定实现顺序，安装产物通过端到端场景才算交付完成。

## 共用客户端之前

改动前，CLI 通过 SDK 打开自己的 Session，HTTP 观察者断开后，服务已能继续完成工具调用。HTTP 提交到忙碌 Agent 时会失败，队列在 Turn 开始时接纳。省略 Session ID 时，服务会生成一个 ID，相对工作区则按服务进程目录解析。共用客户端需要稳定的首次发送标识和显式的工作区路径，以便安全重试并从多个目录接入。[宿主应用](host-apps.md) · [HTTP 服务接口](../reference/server-api.md)

## 职责与客户端契约

| 归属 | 职责 |
|---|---|
| Session SDK | 每个 Session 持有一个日志 writer，每个 Agent 有一条执行链。负责收件队列、Step 准备、工具收尾、等待、取消与恢复。嵌入方可直接调用 SDK。 |
| server | 为产品客户端持有打开的 Session。在服务端机器解析工作目录、模型设置和凭据，执行工具。提供命令、回执、实时状态、持久历史和已保存的输出，所属工作收尾后释放空闲资源。 |
| 共享 Rust 客户端 | CLI 和 TUI 共用连接、提交、关联回复和断线续读的实现。可以在无终端的测试中调用。浏览器使用相同的 HTTP 契约和错误语义。 |
| TUI | 窗口持有草稿、焦点、选中项、滚动位置和显示状态。按键和菜单调用同一组动作，组件渲染状态并发出动作，由一处应用服务端更新并执行外部操作。动画、临时提示与阅读位置由 TUI 自行维护。以后调整快捷键、主题或对话布局时，可以继续使用同一客户端和 Session 格式。 |

Rust 和 Web 用同一组命令、回执、观察事件及错误样例测试。server 根据 SDK 事实提供 Agent 状态和对话条目。每种 SDK 工具都可以通过名称、状态、摘要和可选输出引用展示。文件编辑和命令结果包含 diff 或退出码时，再按工具类型展示这些信息。这样新增工具就有可用的默认显示，也能单独改进某类工具的阅读体验。

### 本地 server 与升级

每个解析后的用户数据目录只运行一个受管本地服务，生效的配置文件路径属于其身份。再次启动时如果指定了另一份配置，显示正在使用的配置及显式切换入口。并发启动时只允许一方创建实例，等服务就绪再发布连接地址，接入时核对身份和协议。从不同项目目录打开的窗口复用匹配的服务。每个本地客户端传入自己解析后的工作目录。远程连接显式选择服务端的工作目录并显示该路径。指定远程地址后始终连接该地址。共享 Rust 客户端统一持有已观察的服务身份，并在启动锁内校验已确认的重启目标。设置流程将同一身份传递到确认和重启；实例被替换时返回目标已变化。

自动启动的本地服务绑定回环地址，服务发现和认证信息只允许当前系统用户读取。工作区、对话历史和执行命令都要求认证，包含回环连接。发行包里的浏览器界面从同一服务的同源入口接入，远程客户端显式认证。模型供应商的凭据由服务持有。[HTTP 服务接口](../reference/server-api.md)

当前开发阶段，仓库内的客户端和服务端共用同一份 Session 协议，随实现一起更新。提供服务状态、构建版本和客户端协议版本。Session 协议不匹配时，仍能发现服务、查看状态和发起正常重启。兼容的新客户端直接接入原服务。协议不兼容时显示双方版本，并给出重启受管服务的入口。执行或工具清理仍在进行时，延后替换并显示是哪项工作占用服务。正常重启时由 server 暂停接纳新提交，先释放 Session writer 再交接。重启后能找回持久等待和排队输入。进程崩溃后按 SDK 的事实显示中断或结果未知，交给用户核对。[健康接口](../../../crates/kuku-server/src/routes/health.rs) · [Session 恢复](../reference/sdk.md)

### 命令与观察

首次发送前确定工作目录、难以碰撞的 Session ID 和命令 ID。回执丢失后原样重用这些身份。如果首次提交只完成了一部分，server 能幂等补齐。独立的创建意图占用同一 ID 时报告冲突。重复提交只创建一个 Session，这条输入只投递一次。后续命令携带 Session、目标 Agent 和命令身份，复用 ID 却改变正文、接收者或投递时机时返回冲突。

界面区分草稿、尚未确认的发送、已持久排队和已接纳的输入。尚未确认的发送在客户端私有存储中保留原目标、命令身份和原始意图。重新打开终端或刷新浏览器时先查询服务端回执。如果 server 查无记录，用户可以原样重发或放弃。处理完即清除这条临时记录。provider 重试由 SDK 负责。模型请求失败或工具结果未知时，界面给出用户可以明确采取的下一步。

可恢复的待处理区固定在终端输入框正上方，显示所选 Agent 尚未确认的发送和排队输入，重开后也能恢复。编辑或撤回排队输入时，与接纳原子判定。如果接纳先提交，显示已接纳状态并保留实际输入。确认撤回后，仅当原 Agent 面板的输入框仍为空时，才将排队文本恢复到该面板；不会覆盖等待期间输入的草稿。

SDK 在每个边界按回执次序接纳符合条件的输入。即使先排了下一轮消息，后来发送的插话仍能进入当前 Turn 的下一 Step。provider 重试沿用已准备的 Step。打断绑定到用户观察到的那次执行。打断后，尚未接纳的输入保留在可见队列里，明确继续或再次发送后才推进。用户可按回执撤回仍在队列中的输入，已经接纳时返回实际状态。提问和授权都标明等待中的 Agent 及具体请求。一个窗口先答复，另一个窗口就会看到已经生效的结果。[Step 准备逻辑](../../../crates/kuku/src/query/frozen.rs) · [SDK 命令](../../../crates/kuku/src/session/runtime/mod.rs)

连接时取得 Agent 快照及与它对应的已提交 Session 游标。先显示该边界处最近的一页历史，向上翻阅时加载更早的页，从游标之后跟随新提交。临时文本和工具进度关联到产生它们的 Agent 和执行，正式结果替换临时预览，按事件 ID 去重。观察者掉线或落后时从持久历史补齐。每次订阅都记录自己的目标，切换 Agent 后，旧订阅的迟到事件不会混入当前对话。浏览器房间观察整个 Session 跨 Agent 的有序流，并通过过滤同一批条目得到每个 Agent 的镜头，因此切换视角不会另开订阅；按 Agent 的观察仍可供终端和按 Agent 过滤的历史读取使用。展开大段工具输出时按 SDK 的输出 ID 和字节偏移续读。[SDK 观察接口](../../../crates/kuku/src/session/runtime/observe.rs) · [持久工具输出](../reference/tools.md)

接入正在运行的 Agent 时，先取得当前请求已流出的有界文本预览，再接收该次执行的后续更新。预览是临时数据。在 Turn 开始或之后的 Step 接纳输入时，都保留可信的发送 Agent 地址，供接收端显示来源。

思考、可见回复、逐步生成的工具参数与工具执行可以交替或重叠。每种显示状态都由证实该活动的事件推导。工具在派发后才开始执行。界面实时显示思考状态。模型服务公开思考文字或摘要时，可在回复上方展开预览。加密与遮蔽的数据不进入对话。

将持久化的重试决定投影到历史记录和接入时的 Agent 进度中。显示事件报告的尝试编号、可选的最大尝试数、权威失败类型及 `Esc` 打断提示；等待倒计时只能使用事件时间戳和策略选择的延迟。历史中的停止原因不应保留实时停止提示。保留有界模型诊断，并仅依据明确错误码给出恢复建议。不得从消息文本或供应商响应头推断重试策略，也不得自动重新提交请求。

创建 Agent 与随后调整设置共用同一模型解析器。即使未配置服务档位，模型也能看到各条路线已知的思考和服务选项。委派创建沿用已配置或默认的服务档位，用户明确要求时可以选择受支持的其他档位。创建卡显示所选预设的名称，直接选路线时显示生效的思考等级。选了具体服务档位才显示该档位。

## 终端交互

高频操作在发起的位置完成，并在附近反馈结果。阅读、编辑或复核需要独立空间时，使用单独的对话框。关闭面板时恢复原有焦点、草稿、选区和阅读位置。

操作、模型和思考设置与输入框共用背景，选项和草稿对齐。常用快捷键放在对应操作附近，`Ctrl+P` 查看完整列表。切换思考档位时，模型和当前档位留在原位，下次请求将使用的档位显示在输入区的反馈行。删除开头的斜杠会关闭命令补全。选项列表支持上下键循环选择。回退历史用上下键按时间顺序浏览用户消息，按上键到顶部会加载更早的消息。

当前活动固定在输入区标题行左侧，阶段图标在原位变化。工具与模型输出同时进行时显示简短的工具数量。输出 token 优先采用当前请求的上游报告，等待报告时可根据可见回复字节数给出带 `~` 的估算。多 Agent 会话显示接收者选择入口。启用的费用栏显示简短的美元金额。轮次之间留一行空白，下一张用户消息卡标识轮次。卡片、输入区和面板使用紧凑内边距。左右按整列取整。可读思考留一行供展开，包括直接接工具调用的回复。展开的思考留在消息内，随对话滚动，直到用户收起。单 Agent 查询等待和完成时使用同一种紧凑行。查询组收起时显示最近结果，展开时每条结果显示一次。直接标明 Agent 查询结果。少量不同类型的工具调用组合时，优先显示已知的逐项结果。命令预览用一行显示调用，让输出容易找到。完整命令和原始参数可在详情中查看。工具和 Agent 卡片复用代码块的圆角边框和底色。展开后各项结果留在同一个框内，可以逐项查看详情。

终端在同一帧提交变更的单元格和编辑光标。写入单元格时隐藏光标，定位后再显示。流式渲染按下一帧的实际时间刷新，轻负载下以 25 毫秒为目标间隔。输入和故障可请求立即刷新。流式 Markdown 复用语义已确定的顶层块排版，宽度或显示方式发生变化时重新排版。仍会变化的结构、已完成及已打断的回复沿用标准渲染器，保留原文供阅读和复制。

在交互终端运行 `kuku` 后，按所选工作目录打开一个空白全屏窗口。新会话页展示工作区、已解析的起始模型和服务端为该工作区发现的 Skills。工作区和模型信息与 Skills 名单分区，浏览入口放在名单旁。首屏信息使用终端底色，和输入框正文左对齐。空间足够时，在信息下方提示命令列表、选模型、切思考和帮助的快捷键。每次新建草稿时刷新 Skill 名单。首次明确发送时才创建 Session。本地数据目录尚未配置时，引导使用现有初始化流程。远程配置有误时，指出需要在服务端修正的设置。显示实际连接的 server、工作目录和模型或 Tier，修正配置期间保留草稿。环境变量凭据由加载它的 server 进程持有。更换环境后需要重启时，引导到服务状态和重启入口。在非交互终端提示可用于脚本的入口。脚本命令沿用已文档化的输出格式和退出行为。[配置指南](../start/configuration.md) · [CLI](../reference/cli.md)

终端工作台采用平面布局。会话身份常驻顶部，轮次以带编号的分隔线起始，用户消息有独立色面，输入区随文字增高。助手正文与工具结果分开呈现，Markdown 随输出逐步排版，表格随宽度调整，可见工具共用一处快捷键提示。关联 Agent 默认收起，支持键盘、鼠标展开。发送回执表示已送达，执行阶段、流式文字、待用户决定事项与结果均来自对应 Agent 的观察数据。共享样式由终端主题模块维护。输入区顶部并排显示 kuku 圆环和阶段名称。工作期间缺口沿环移动，各阶段共用一个节奏。结束后圆环闭合静止，流式文字到达时图标宽度固定。状态变化时保持布局稳定，区分服务方已报告的思考、正在输出正文和等待首个事件。底栏可按需启用执行字段。新建会话显示有辨识度的 kuku 标题，工作开始后收为一行。Agent 列表和会话查询默认按参与者和活动提供摘要，详情保留原始结果。[OpenCode 会话](https://github.com/anomalyco/opencode/blob/63bfe62c91fb069c97fcdd7a721aa8f7291cbf49/packages/tui/src/routes/session/index.tsx) · [omp 对话组件](https://github.com/can1357/oh-my-pi/tree/e1ae2cc998efd1ca151b46ebefc0e0dab6c23c63/packages/tui/src/chat) · [Pi 终端](https://github.com/earendil-works/pi/blob/e56d35ce5eceedfa16eaf13a5f01a1f7b7271253/packages/coding-agent/docs/usage.md)

打字时状态栏的位置保持稳定。桌面上使用一行。手机宽度且高度充足时，第一行显示身份，第二行显示工作区和用量。草稿、排队和回执在输入区反馈，显示字段可配置。TPS 按所选 Agent 已测请求的总输出与总耗时计算。缓存命中率使用同时报告输入 token 和缓存读取 token 的请求，两项合计使用同一批样本。重连时保留已知用量，缺测项明确标记。区分连接问题与执行失败。Windows 后台命令工具执行时不弹出控制台窗口。

轮次统计固定在输入区上方。跟随输出时显示最新轮次，翻阅历史时跟随视口顶部的轮次，同时显示可用的耗时、输入和输出 token、缓存命中率及实际工具调用次数。卡片不占用输入焦点，窄屏优先保留正文。活动标记旁每秒更新当前轮次的已用时间，例如 `1h 05m 54s`。思考、正文输出和工具执行沿用同一个轮次起点，切回该 Agent 时恢复这份计时。

活动状态栏保持稳定，合并相关阶段并抑制短暂切换引起的闪动。发生错误或需要用户操作时立即显示。翻阅较早输出时，返回最新内容的入口紧贴输入区。点击入口，或按 Ctrl+End、Alt+↑，均可恢复跟随输出。

常规终端尺寸下，输入区、面板和消息卡片的底边内侧留一行空白，沿用正文底色。卡片之间的间隔单独保留。

默认状态栏最左侧显示生效模型。宽屏默认底栏将身份与用量分组，窄屏和自定义布局保留字段顺序。等待、失败和需要操作的状态用颜色和文字同时表达。在编辑器中预览状态栏变化，字段顺序保存在终端本地偏好中。输入区和弹窗共用间距、选择与焦点样式。常规高度下给输入区和底栏留出外间距。`To <agent>` 收件人与可编辑正文之间留出清晰间隔，窄屏也能辨认 Agent 名称。Agent、模型和执行详情弹窗支持鼠标浏览和选择。有执行副作用的操作须按 Enter 明确确认。窄屏优先保证正文可读、输入可编辑。

| 操作 | 成品行为 |
|---|---|
| 写提示词 | `Shift+Enter` 或 `Ctrl+J` 换行。多行粘贴形成一份可编辑草稿，输入框将 CRLF 和单独的 CR 统一成 LF。支持软换行、中文输入、按用户感知的字符移动光标以及已发送提示词历史。菜单中 `Tab` 只补全输入，方向键移动高亮项，`Enter` 执行。`Ctrl+P` 或 `F1` 打开只读快捷键帮助；在帮助中按 Enter 或点击不会执行操作，草稿保持不变。草稿为空时按 `/` 才打开可搜索的动作与 Skill 菜单。Skill 与内置命令重名时，可从标明类型的条目选择。`@` 和路径补全插入工作区相对路径文本，按选中服务端工作区的可见范围查找。需要文件内容时通过已有读取工具获取。 |
| 清空草稿或退出 | 在主界面按 `Ctrl+C` 清空当前草稿。草稿为空时，按键沿用 `/quit` 的退出流程。弹窗中的输入框只清空自身内容。 |
| 找到对话 | `/new` 打开空白草稿，原 Session 继续工作。`/resume` 在所选工作区搜索 Session。预览前就能看到可辨认的标题或首条提示词节选、最近活动和等待状态。Alt+←、Alt+→ 按当前 Session 的固定顺序直接循环切换 Agent。编辑草稿时也可用 `/agents` 搜索，查看身份、当前或排队任务和待决事项。存在时显示“上一个 Agent”控件。预览或切换不发模型请求。每个目标的草稿和滚动位置留在当前窗口。 |
| 上下文控件 | 编辑器之外，F2 按顺序循环可见控件：请求、可用的认证修复、继续或停止、待确认投递恢复、上一个 Agent、服务操作和 Messages。控件聚焦时，Tab/Shift+Tab 向前或向后移动。Enter 才执行已聚焦控件；点击有副作用的控件只聚焦。Messages 选择器先显示活动消息，再显示独立的“Rewound · read-only”分区。回退组不属于活动消息或模型上下文；展开后焦点转到历史阅读。可用的 Retry 和 Load earlier 选项仍是独立的只读组操作。离开 Messages 选择器或组阅读器时按 Esc 返回输入框，并保留草稿文本和光标，不会启动双 Esc 回退计时。Running 或清理阶段按 Esc 会打断，即使控件有焦点；其他状态下 Esc 返回输入框。Waiting 权限焦点可用 Esc 离开，也可按 F2、←、Enter 键盘拒绝。清理完成后，任何 Interrupted Agent 均显示 Continue，即使队列为空；Idle 或 Stopped Agent 仅在仍有排队输入时显示。若没有可恢复输入，Interrupted 状态下的 Advance 会将 Agent 恢复为 Idle，而不会启动新的执行；本地重启仍保留原有的所有权保护。Continue 回执提示应短暂显示，且不得替换已有错误。窄终端也须完整显示 Esc 对应的动作。 |
| 发送与插话 | 发送后立即在对话中显示该条消息。发送中、回执确认、排队、实际进入轮次和失败状态跟随同一条消息。重试和重新连接按命令标识核对。`Enter` 让空闲 Agent 开始工作。忙时先持久收件，等在途响应及已派发工具收尾，在当前 Turn 下一次模型请求准备前接纳。如果当前 Turn 已自然结束，该输入转入下一 Turn。`Alt+Enter` 排到下一轮。 |
| 队列编辑与撤回 | 在输入框正上方保留 Pending inputs 条。草稿为空时按 ↑ 进入队列焦点；点击可见的普通排队行会选中其持久命令身份。按 ↑/↓ 浏览可编辑队列，Enter 打开现有的独立编辑器，Delete 撤回所选输入。空闲或 Waiting 时按 Esc 返回输入框；Running 或清理阶段会打断，不论队列是否有焦点。队列增长时保持所选行可见。排队回执先于完整快照到达时，保留所选身份和明确的编辑或撤回意图，等该条输入详情到达；目标、焦点或草稿变化时取消等待，不得把有界投递预览当作可编辑正文。每次变更前按身份重新验证；若选择已过期则报告状态，不得操作其他行。保留草稿，并排除非普通 host 输入。 |
| 打断与离开 | `Esc` 首先关闭答案编辑器，按问题 ID 保存未提交答案草稿且不改变主输入框草稿。否则 Running 或清理阶段会打断，即使队列、请求或上下文控件有焦点；空闲或 Waiting 且有焦点时返回输入框而不产生副作用。空闲且输入框为空时连按 Esc 两次打开消息回退。打断会保留主草稿和该轮已输出的部分正文，重开仍可阅读，并显示清理进度或失败原因。随后按 `Enter` 才发送草稿。退出窗口只断开观察，其他 Agent 和已接下的工作继续由 server 持有。 |
| 消息回退 | 空闲且输入框为空时，双 Esc 打开最近的用户消息。到达列表顶部边界后按需加载更早历史，限制缓存大小并保持单次请求在途。前插一页时按事件身份保留所选消息，显示加载及重试反馈。确认前读取精确的原始用户消息，不得用有界对话预览作为回退正文。Esc 关闭选择器，不改变草稿或 Session；只有确认才回退所选消息。[Session 语义](../how-it-works/sessions.md#消息回退) |
| 阅读与答复 | 让标题层级易辨认，并流式呈现代码围栏。标注已知语言，限制高亮工作量，未知语言按纯文本显示。助手回复中，明确标注为 Markdown 的围栏默认预览其中的文档，包括表格与内层代码块。在同一 Agent 中可切换查看原文。工具活动使用紧凑的平面卡片。同一 Agent 的同一轮次中，连续成功的读取、搜索和列举可跨工具归为一张卡，显示调用数与种类。文件变更、执行中和失败的操作单独可辨。写入和编辑有独立文件卡片，显示路径、有限行数的内容或差异预览，以及工具结果可确认的行数统计。运行中、等待决定和失败的条目保持醒目。展开组后显示紧凑的调用行，再逐条查看目标、参数和结果。鼠标和键盘使用同一详情操作。收放详情或收到新输出时保留阅读位置，回到底部后继续跟随。安全呈现终端控制字节，并保留原始输出供读取。复制已提交的助手回复时使用原文，鼠标选区只复制选中的文字。所选 Agent 的待决问题或权限会在输入框上方自动显示但不抢焦点。按 F2 或点击问题卡片会直接打开绑定该请求的答复编辑器；Esc 关闭编辑器并按问题 ID 保存答案草稿，重新进入时恢复，且不改变主输入框草稿。按 F2 或点击权限卡片会聚焦卡片；必须明确选择 Deny 或 Allow once 后按 Enter。Waiting 时 Esc 离开权限焦点而不作答；键盘拒绝路径为 F2、←、Enter。 |
| 选模型与恢复 | `/model` 与 `/thinking` 为选中 Agent 提供已配置的连接、Tier、模型 ID 和受支持的思考设置。显示当前生效值及等待生效的更改，在尚未准备请求的安全边界应用。指出问题来自连接、server 配置、provider 还是工具，并提供相应的恢复动作。 |

受管本地服务发生结构化认证失败时，为实际失败的连接和模型提供凭据修复。准备和保存都绑定该失败、路由和服务身份，只修改对应凭据。保存并重启本地服务必须是明确动作，并遵循现有忙时重启保护：重启被推迟时，不能把已保存凭据报告为已生效。确认新服务实例和配置后，恢复同一 Session、Agent 和草稿，再由用户明确继续原输入。远程或使用 token 的连接只提供服务端修复指引。不探测认证，也不自动重试。[配置指南](../start/configuration.md#认证失败后的恢复)

## 实现顺序

1. **打通共享执行路径。** 补齐 SDK 在 Step 和 Turn 边界的输入接纳，复用其观察、输出读取及待决回复接口。实现本地服务发现、server 契约和无界面的 Rust 客户端，再将 CLI 的执行和观察命令接入。同一改动中迁移仓库内调用方并移除被替换的路由或执行路径。验证首次发送重试、两个工作区共享服务、忙时投递和断开重连。[核心方向](core-direction.md)
2. **交付默认终端入口。** 用 Ratatui 排版、Crossterm 接收终端事件。输入编辑和对话渲染独立于网络时机，通过共享客户端实现上面的日常操作。按需翻页读取旧历史，为视口缓存和实时更新设上限，流式输出期间维持阅读位置。正常退出和可处理的错误都恢复终端模式、光标及粘贴设置。[Crossterm 事件](https://docs.rs/crossterm/latest/crossterm/event/struct.EventStream.html) · [Ratatui TestBackend](https://docs.rs/ratatui/latest/ratatui/backend/struct.TestBackend.html)
3. **交付安装后的使用体验。** 发行包从同一服务提供现有 WebUI。通过 `kuku web` 或 TUI 菜单打开浏览器，接入该服务，带上已选的工作区、Session 和 Agent。浏览器接入时完成认证，可复用的凭据不写入链接或日志。`kuku server` 继续提供显式运行服务的入口。浏览器共用寻址、状态、回复、插话与打断契约。验证在浏览器里接着处理 TUI 发起的工作，再回到终端。按已交付的入口更新安装、快速上手、CLI 和 server 参考文档，把新增检查接入项目已有验收入口。浏览器自身的交互模型、token 系统与交付阶段归 [Web 客户端](web-client.md)。[现有 WebUI API](../../../apps/web/src/api) · [发行打包](../../../.github/workflows/release.yml) · [测试指南](../contributing/testing.md)

| 画面与输入 | 驱动动作并渲染宽窄窗口。覆盖空白配置、粘贴、修改状态栏偏好和重启、带未发送草稿切换和返回、等待、错误与原目标的迟到事件。使用含代码、列表和表格的中文流式长答，以及至少 20 次混合成功、失败和运行中的同轮工具调用。核对简略和展开视图、复制、阅读位置及下次发送的接收者。[安装客户端验收](../contributing/testing.md#安装客户端验收) |
