# Sessions

`Session` 拥有一组 Agent 的持久历史、writer、命令输出和活动运行资源。直接嵌入公开 SDK，无需 daemon 或 CLI 子进程。操作与调用程序见 [SDK 参考](../reference/sdk.md)。

## 身份与所有权

Agent 使用稳定的 Session 内扁平地址，例如 `main`、`reviewer` 或 `agent-3`。保留中的地址不能转交。新 Agent 从独立上下文开始；可复用行为 Preset 提供初始指令与默认值，不复制其他 Agent 的历史。显式配置仅影响对应 Agent。

## 投递与推进

创建、配置、投递、回复和定向执行控制接收调用者命令标识。相同标识和内容返回原持久回执，冲突复用失败。投递、模型接纳、执行完成分别记录。

`Activation::Wake` 请求推进，`Activation::Enqueue` 保存输入以便宿主显式调度。运行中的 Agent 按回执顺序在安全边界接纳符合条件的输入。`InputTiming::NextStep` 允许在当前轮的下一次模型请求前接纳，需等在途响应和已派发工具收尾。如果当前轮先结束，这条输入仍可以在下一轮接纳。`InputTiming::NextTurn` 始终等到下一轮，即使后来的 `NextStep` 输入先被接纳。技术性重试沿用已经准备的请求。

默认情况下，Turn 持续执行工具步骤，直到模型完成、执行等待或停止，或触及资源限额。

每个 Agent 最多有一条推进链，不同 Agent 可并发。定向取消使用所观察到的执行标识。取消后，排队输入仍可见，可以显式推进或由宿主发送新的唤醒输入。尚在排队的输入可以按回执标识撤回。撤回与接纳发生竞争时，操作返回实际状态。

执行独立于观察。`agent_view` 返回 Agent 快照、排队输入和对应的已提交游标。`events(after, limit)` 返回有界持久分页。`observe(after)` 组合可续接的持久游标和按 Agent、执行标识关联的有界临时更新。慢消费者收到落后通知，仍能查询持久结果。

## 后台 Job

Session 用 Job 句柄跟踪已派发的命令或工作区脚本。Job 归发起它的 Agent 所有，可以在该 Turn 结束或客户端断开后继续运行，执行期间仍会占用执行宿主的资源。前台观察窗口决定工具何时返回句柄。显式设置的进程截止时间在转入 Job 后继续生效。[工具参数与 Job 句柄](../reference/tools.md#session-job)

仅达到观察时限不会触发模型请求。Session 记录终态并向所属 Agent 的收件箱投递有界结果。该 Agent 可在当前或下一 Turn 的安全边界接纳结果，无需轮询。Session 保持打开时，客户端可以检查或取消指定 Job。[终端控制](../reference/cli.md#终端界面) · [SDK 方法](../reference/sdk.md#工作区执行)

定向停止已观察到的 Agent 执行时，已经分离的 Job 继续运行。`Session::cancel(agent)` 停止指定 Agent 并取消其 Job。关闭 Session 会取消所有仍在运行的 Job，等待清理和持久写入。如果运行时在记录终态前停止，重开时会将未结算的 Job 标记为 `interrupted`。显式启动新工作前，先检查可观察到的副作用。

## 存储与上下文

[Session 布局](../reference/file-layout.md#session-layout)包含唯一权威 `events.jsonl` 和保留输出。共享 writer 持有操作系统锁，增量追加并同步记录。打开时修复不完整尾部，拒绝已提交历史损坏。

Agent 创建／配置、投递／接纳、Step 准备、授权、派发、结果、等待、回复与结算分别记录。Turn 完成或模型措辞不证明业务成功，应检查实际文件、命令结果和判定器。

provider 可见的 system 文本、prelude、工具和已接纳 canonical 消息冻结在上下文段中。每条消息在该段接纳一次，准备好的 Step 记录段与消息边界、连接／设置、关联和请求 hash，不重复追加完整线路请求。使用相同路由和能力重开时，会保留已提交前缀。明确的上下文、工具或交接变化可以建立已提交后继段。

每个 Agent 上下文段都会保存准备该段时使用的 provider 能力，以及非敏感的 query connection、model 和 tier 选择器。这是每个 Agent 的 provider 上下文缓存边界，不是整个 Session 共用的能力锁，也不保存凭据快照。API key 轮换仍会实时生效，不会改变上下文段。被动修改 endpoint、协议、model、connection profile 或能力时，运行会在历史投影、新上下文接纳或 HTTP 派发之前停止，不会创建后继段。恢复记录的配置后可继续。

建立后继段必须有持久化的 connection、model 或 tier 选择变更，可通过 `configure_agent` 或带有配置的输入记录；仅修改 instructions／tools 或发生 handoff 都不能授权 provider 路由漂移。明确的路由转换会建立带有全新缓存前缀的后继段：旧段及其已接纳记录保持不变，后继段只投影受支持的文本及工具调用／结果历史，并省略不兼容的 provider 原生续接数据。

两项新增快照字段都缺失的旧段，会使用精确的更新前签名和已记录的有效 connection、protocol、model、endpoint 进行匹配。匹配时保留原段、原签名和已接纳前缀；历史能力仍未知。仍对原始历史运行严格续接验证：已签名原生续接及可移植的文本／工具历史可以继续，未签名或不兼容的原生续接会被拒绝。assistant 思考若没有持久化 provider replay 决策则含糊，必须安全失败。旧段有效路由变化或仅有部分快照字段时安全失败，并提示恢复已记录路由或新建 Session。不得臆造历史元数据或重写旧签名；之后合法的上下文／交接变化会创建带当前快照的后继段。

行为 Prompt 仍是外部或内嵌的版本化资源，与上下文选择、provider 转换分离。原生协议续接数据随 assistant 响应保存，不能静默跨不兼容协议使用。

## 消息回退

已提交消息回退按 Agent 和精确的用户消息事件标识定位。它向日志追加回退操作，并在活动投影中隐藏从目标消息开始、到回退提交之前的有界区间。原始事件仍保留在只追加日志中，回退后提交的新输入仍然可见。在 TUI 中，空编辑框时连续按两次 Escape 可选择已加载的已提交消息并确认；原文会放回编辑框，但不会自动发送。默认不恢复文件；显式选择后，也只恢复受支持且已记录的工作区内文件变更，不会撤销 shell 或外部副作用。

## 等待与回复

存在待决授权时，用 `reply_permission` 回复对应的请求标识和 Agent。[工具授权与延后审批](permissions.md)

`ask_user` 持久保存问题，一次返回等待句柄；当前工具批次结束后让出执行。`reply_question` 仅向匹配待决请求投递关联输入。重开重建等待；无关、内容冲突的重复回复或过期回复不能授权其他动作。等待不轮询模型，也不占模型名额。

## 输出与清理

命令 stdout/stderr 从首字节经有界帧写入 Session 文件。首次模型视图是有界预览或识别的构建／测试摘要，携带保留引用与明确过滤／不完整标志。`read_output` 支持有界范围、字面搜索和增量偏移。超配额后继续排空管道并标记不完整。

Agent 可以为捕获建立[命名值](../reference/tools.md#命名会话值)。普通捕获可能到期。给输出命名或随输入投递时会保留引用的字节，重开后可以继续读取。替换名称后，已投递的引用仍然有效。长期交付物可作为普通文件写入工作区。

取消时，Unix 进程组和 Windows Job 对象负责清理进程树。主动逃离不在可信本地进程边界内。继承管道具有清理截止时间。已知清理不完整会持久记录，取消或关闭会报错。

`close().await` 在[清理](#后台-job)后释放 writer。待处理输入和可恢复的等待会保留。打开时不会自动激活 Agent 或重放被中断的副作用。Provider trace 是可选诊断日志，与 Session 事实分开。
