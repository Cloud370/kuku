# Session 机制

一个 `Session` 管着一组 Agent 的持久日志、共享写入锁、保留的命令输出和活跃执行状态。直接嵌入 Rust SDK 就能在进程内使用，不需要守护进程或 CLI 子进程。完整 API 见 [SDK 参考](../reference/sdk.md)。

## 身份与所有权

Agent 在 Session 内使用扁平、稳定的地址（如 `main`、`reviewer`、`agent-3`），创建后永不转交。新 Agent 从干净上下文起步——Preset 只提供初始指令、Tier 和工具默认值，不会复制其他 Agent 的历史。显式配置覆盖只影响对应 Agent。

## 投递、调度与观察

创建、配置、输入投递、回复和定向取消都接收调用方传入的 `command_id`。相同 ID 与内容会返回原持久回执，同 ID 换内容则直接报错。投递、模型接纳、Turn 完成是三条独立记录的事实。

- **激活方式**：`Activation::Wake` 触发推进；`Activation::Enqueue` 只把输入放进队列，等宿主显式调度。
- **接纳时机**：运行中的 Agent 按回执顺序在安全边界接纳输入。`InputTiming::NextStep` 允许在当前 Turn 的下一次模型请求前进入（等在途响应和已派发工具收尾；若当前 Turn 先结束则顺延到下一 Turn）；`InputTiming::NextTurn` 严格等到下一 Turn，哪怕后来的 `NextStep` 先被接纳。
- **自动重试**：技术性重试直接沿用已准备好的请求，仅针对**流式输出开始前**识别出的暂时性 Provider 故障；一旦开始吐字就不再自动重试。
- **Turn 推进**：默认持续跑完工具 Step，直到模型结束、暂停/停止或触及资源限额。
- **并发与取消**：单个 Agent 同时只有一条执行链，不同 Agent 可并发。定向取消绑定观察到的执行 ID，取消后排队输入仍保留（显式推进或发送新的唤醒输入即可恢复）。排队中的输入可以按回执 ID 撤回；若撤回和接纳撞车，接口会如实返回实际状态。
- **观察解耦**：执行不依赖观察者是否在线。`agent_view` 返回快照、排队输入与对应游标；`events(after, limit)` 分页读持久日志；`observe(after)` 把可续接的持久游标和按 Agent/执行 ID 标记的有界实时增量合在一起。慢消费者会收到落后提示，随时可回退到持久查询。

## 后台 Job

耗时较长的命令或工作区脚本可以转成 **Session Job**。Job 归发起它的 Agent 所有，在当前 Turn 结束或客户端断开后仍会继续运行（并占用宿主资源），显式设置的进程截止时间照常生效。前台观察窗口决定了工具何时返回 Job 句柄而不继续阻塞。[工具参数与 Job 句柄](../reference/tools.md#session-job)

单单到了观察时限不会触发模型请求。Job 结束时，Session 记下终态（非零退出码或被信号杀死即标为失败），并把有界结果和保留输出 ID 投递进所属 Agent 的收件箱。Agent 在下一个安全边界就能接纳结果，无需轮询；客户端把它渲染为运行时反馈（不作为消息回退目标），Session 打开期间随时可以查看或取消指定 Job。[终端界面](../reference/cli.md#终端界面) · [SDK 方法](../reference/sdk.md#工作区执行)

- 定向停止当前 Agent 执行，不会杀死已经分离的 Job。
- `Session::cancel(agent)` 会停止该 Agent **并**取消其名下所有 Job。
- 关闭 Session 会取消全部活跃 Job，并等待清理与落盘完成。
- 如果进程在 Job 落盘终态前异常退出，重开时会把未结算的 Job 标为 `interrupted`——重试前先检查实际副作用。

## 存储与日志封存

每个 [Session 目录](../reference/file-layout.md#session-layout)包含唯一权威的 `events.jsonl` 和保留输出。共享 writer 持有操作系统文件锁，增量追加并同步写入；打开时自动修复残缺尾行。封存过的前缀内嵌运行时检查点，重开时直接恢复状态、只重放未压缩的尾部。改动模型请求字节上限不会让检查点失效（真正执行时再按当前上限重建启动上下文）；检查点不可用时自动退回全量重放。压缩帧读取时会做完整性校验。[重开耗时与内存实测](performance.md#重开大型-session)

### 日志何时压缩

运行时在 Session 正常关闭、任务与落盘全部结算后检查是否封存（SDK 发生在 `Session::close()`；服务端会在空闲时关闭运行时 Session——退出 TUI 只是断开客户端）。

- 首次封存门槛：**32 MiB** 已提交日志。
- 后续封存需未压缩尾部**同时**达到 **32 MiB** 和当前已封存前缀的磁盘体积（比如前缀 65 MiB，就需要至少 65 MiB 的新日志）。
- 只有压缩后的新文件更小时才原子替换，完整逻辑历史依然可通过 [`kuku events`](../reference/cli.md#kuku-events) 查阅。

## 模型上下文与压缩

Provider 可见的 system 文本、prelude、工具定义和已接纳的规范消息会冻结在一个**上下文段（context segment）**里。每条消息在该段只接纳一次，每个准备好的 Step 只记录段与消息边界、生效线路/参数、关联 ID 和请求 hash，不重复存整包请求。沿用相同路由和能力重开时，已提交前缀完整保留。

- **主动压缩**：接近字节或 token 上限时，运行时可让模型为较早的工作生成一份有界检查点，同时保留当前输入和最近的完整工具批次。检查点会记录已交付回复与续跑证据，原始工具结果和保留输出依然可读；检查点落盘后后继段才生效。
- **超限兜底**：如果 Provider 在开始吐字前因上下文超限拒收请求，且开启了自动压缩，Agent 可以尝试压缩一次并在同一 Turn 用更小的请求补发（被拒的那次仍计入请求预算）。
- **手动压缩与撤销**：Agent 空闲时，用 `Session::compact_command` 或 TUI 的 `/compact` 手动总结早期上下文，不会开启新 Turn 或再发回复；失败或取消时原上下文完好无损。`Session::restore_context_command` 或 `/compact undo` 会恢复到最近一次生效压缩之前，同时保留之后的可见消息。
- **路由与能力快照**：每个 Agent 的上下文段都快照了当时的 Provider 能力及非敏感路由选择器（`connection`、`model`、`tier`）。这是单 Agent 维度的缓存边界，不是凭据快照——轮换 API key 实时生效，不会破坏上下文段。被动更改 endpoint、协议、模型、配置档或能力时，会在投影或发请求前安全中止（恢复原配置即可继续）。有意切换线路需要通过 `configure_agent` 或带配置的输入留痕，开启带新缓存前缀的后继段，并迁移可移植的文本与工具历史。
- **兼容旧段**：缺少新快照字段的旧段按精确的旧签名加上记录的连接、协议、模型和 endpoint 匹配，继续执行严格重放校验（带签名的原生续接和可移植文本/工具历史照常继续，含糊的未决思考或旧路由被改则安全失败，不臆造历史元数据）。

行为 Prompt 资源始终与上下文选择、Provider 协议转换解耦。协议原生续接数据绑定在对应 assistant 响应上，不会静默跨不兼容协议使用。

## 消息回退

回退到已结束的某一轮，会把对话恢复到该轮结束时的状态，原分支仍保存在同一个 Session 里（重开时记住当前选中的分支）。下一次请求复用该轮冻结的供应商前缀与生效压缩结果，缓存过期时间由供应商决定。

可选的文件恢复只处理当前分支中该轮**之后**可核验的改动——依据直接调用内置 `write_file` / `edit_file` 时写入日志的版本，恢复旧内容或删掉新建文件。Shell 与脚本改动留在磁盘上，日志版本或当前内容核对不上时自动跳过。切回之前保存的分支时只恢复对话，不动文件。[终端操作](../reference/cli.md#回退与分支切换) · [历史 API](../reference/server-api.md#快照历史与观察)

## 等待与回复

- 待决授权：用 `reply_permission` 传入精确的 `request_id` 和 Agent 回复。[工具权限](permissions.md)
- `ask_user`：把问题落盘一次，当前工具批次结束后让出执行权，只有匹配的 `reply_question` 才能恢复。

等待中的 Agent 不轮询模型，也不占并发名额。无关、冲突或过期的回复绝不会授权任何动作。

## 输出与清理

命令的 `stdout`/`stderr` 从第一个字节起就按有界帧写入 Session 目录下的文件。模型先看到的是有界预览（或识别出的构建/测试摘要），附带保留输出引用以及明确的截断/过滤标记，需要看更多时调 `read_output`。超过配额后管道仍会排空，并把捕获标为不完整。

Agent 可以给捕获绑定[命名会话值](../reference/tools.md#命名会话值)。普通捕获可能过期清理，而命名值或随输入附带的引用会跨重开持久保留字节（覆盖名称不影响已投递的旧引用）。长期交付物请直接写成普通工作区文件。

取消时通过 Unix 进程组和 Windows Job 对象清理进程树（主动逃逸超出可信本地进程边界；继承管道设有清理超时）。已知清理不完整时会记入日志，并让取消/关闭返回错误。

`Session::close().await` 会先取消活跃 Job、等清理落盘后再释放写入锁。重开不会自动唤醒 Agent 或重放被中断的副作用。Provider trace 是独立的可选诊断日志，与 Session 事实分开存放。
