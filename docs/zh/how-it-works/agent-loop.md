# Agent 执行循环

Agent 从收件箱接纳新工作时，就开始一个 **Turn**。一个 Turn 里可以包含多个 **Step**；每个 Step 对应一次逻辑模型请求，以及该响应发起的整批工具调用。

## 从输入到结果

1. **提交与接纳**：Session 先把输入落盘并返回回执，运行时在 Turn 开始时（或安全的 Step 边界）接纳符合条件的输入。
2. **准备与请求**：SDK 装配该 Agent 的上下文、记录 Step 元数据，再发出模型请求。响应传输期间，客户端可以实时查看流式增量。
3. **校验与执行工具**：如果模型返回了工具调用，运行时先校验整个批次，再把每个调用绑定到解析后的参数与工具定义、过一遍权限审批、记录派发并提交结果。互不冲突的调用可并发执行，冲突的工作区操作按顺序排开。
4. **继续或结束**：下一 Step 接收已接纳的工具结果视图。不带工具调用的响应会结束当前 Turn，只有归一化后的终止状态为成功时，Turn 才算成功完成。

Session 持有的 Agent 请求如果撞到输出长度上限，Turn 会直接中断，不完整的工具调用批次绝不会被派发。直接执行的 `Query` 和子 Agent 查询遇到输出上限时，可以沿用原配置并附带一条运行时恢复提示重试一次；再次撞上限或无法发送时同样中断。不完整响应仍会留在日志里备查，但不会回放进模型上下文。

用 `kuku show SESSION_ID --agent AGENT` 查看落盘结果。Turn 结束不代表任务真的做好了——检查实际文件改动、命令输出或测试才是依据。[事件参考](../reference/events.md) · [Session SDK](../reference/sdk.md)

## 等待、中断与交接

- **等待**：`ask_user` 提问或延后工具授权会让 Agent 让出执行权，直到宿主提交对应回复（重开 Session 后依然有效）。
- **取消**：取消 Agent 会停止新的派发，并等待它名下正在跑的工作收尾。
- **派发后结果未知**：外部动作派发后如果发生中断，先核实外部实际状态，再决定是否重试。
- **上下文交接**：压缩生成摘要并保留最近几轮后，SDK 会提交后继上下文段，旧段依然能从日志完整追溯。
