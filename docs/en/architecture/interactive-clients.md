# Interactive clients — server, Rust TUI and WebUI

The delivery target is the installed `kuku` binary a developer can use for a whole coding task. Open it in a project, configure a model, submit work, inspect a tool result, answer a question, steer a busy Agent and pick up the same work from another terminal or browser. Installing a new client while a tool is running must allow that work to finish on its server. The stages below give the implementation order. Delivery is complete when the installed product passes the end-to-end scenarios.

## Before the shared client

Before this change, the CLI opened its own Session through the SDK, and the server already let tools finish after HTTP observers disconnected. HTTP submissions to a busy Agent failed, and queued input was admitted at Turn start. The server supplied a Session ID when one was absent and resolved relative workspaces from its process directory. A shared client needs stable first-send identities and explicit workspace paths to retry safely and connect from multiple directories. [Host applications](host-apps.md) · [Server API](../reference/server-api.md)

## Ownership and client contract

| Owner | Responsibility |
|---|---|
| Session SDK | Own one journal writer per Session and one execution chain per Agent, including the inbox, Step preparation, tool settlement, waiting, cancellation and recovery. Embedders can call the SDK directly. |
| Server | Own the open Sessions for product clients. Resolve workspaces, model settings, credentials and tools on its host. Expose commands, receipts, live state, committed history and retained output. Release idle resources after owned work settles. |
| Shared Rust client | Give CLI and TUI one implementation of connection, submission, correlated replies and resumable observation. Its API can be exercised without a terminal. The browser uses the same HTTP contract and error meanings. |
| TUI | Keep drafts, focus, selection, scroll and presentation in the window. Translate keys and menu choices into actions. Widgets render state and emit actions. One place applies server observations and dispatches effects. Animation, temporary feedback and reading position stay local to the TUI. A new shortcut, theme or transcript layout can use the same client and Session format. |

Give Rust and Web one set of command, receipt, observation and error examples to test against. Derive Agent status and transcript entries from SDK facts at the server boundary. Every SDK tool can render through its name, status, summary and optional output reference. File edits and commands can add a diff or an exit code when the result contains one. A new tool then has a usable display before anyone designs a special widget.

### Local server and updates

Manage one local service per resolved user data home. Check the effective configuration path as part of its identity. A second launch with a conflicting configuration reports the active profile and a deliberate way to switch. Serialize startup, publish its endpoint when ready, and verify identity and protocol when attaching. Client windows launched from different project directories reuse the matching service. Each local client sends its own resolved workspace. For a remote connection, select a workspace on the server and display that path. An explicit remote address always uses that endpoint.

The managed local listener binds to loopback. Restrict its discovery and authentication material to the local user. Require authentication for workspaces, transcripts and commands, including on loopback. The packaged browser enters through the same service with same-origin access, and remote clients use explicit authentication. Provider credentials stay with the server. [Server API](../reference/server-api.md)

During development the in-tree clients and server share one current Session schema and change together. Expose service status, build and client protocol revision. Keep discovery, status and orderly restart usable when the Session protocol differs. A compatible new client attaches to the running service. On an incompatible protocol, report both versions and a way to restart the managed service. Defer replacement while an execution or its tool cleanup is active and show what is keeping the service busy. On an orderly restart the server gates new submissions, releases its Session writers and then hands over. Durable waits and queued inputs survive. A crash surfaces the SDK's interrupted or unknown outcome for user review. [Health response](../../../crates/kuku-server/src/routes/health.rs) · [Session recovery](../reference/sdk.md)

### Commands and observation

On the first send, establish the workspace, a collision-resistant Session ID and a command ID before transmission. Reuse them if the receipt is lost. The server can finish a partially completed first submission idempotently and reject a conflicting creation intent. Replaying the submission creates one Session and delivers that input once. Subsequent commands carry the Session, target Agent and command identity. Reuse with different text, recipient or timing returns a conflict.

Distinguish a draft, an unconfirmed submission, a durable queued input and an admitted input. For an unconfirmed send, keep its original destination, command identity and intent in private client storage until resolved. After a terminal restart or browser reload, check the server receipt first. If the server has no record, offer to resend the original command or discard it. Remove the pending entry after resolution. Provider retries belong to the SDK. A failed provider request or uncertain tool outcome offers an explicit next action.

Keep the recoverable pending area directly above the terminal composer. Show the selected Agent's unresolved submissions and queued inputs there, including on reopen. Edit or withdraw a queued input atomically against admission. If admission commits first, show the admitted state and keep the actual input intact.

The SDK admits eligible inputs in receipt order. Steering may precede an earlier next-Turn follow-up at the next Step boundary. Provider retries reuse the prepared Step. Interruption addresses the observed execution. After interruption, unadmitted inputs remain visible and paused until explicit continuation or a new send. An explicit withdrawal addresses a queued receipt and succeeds only before admission. Questions and permissions identify their pending request and show which Agent is waiting. A second window learns the settled outcome if another client answered first. [Prepared Steps](../../../crates/kuku/src/query/frozen.rs) · [SDK commands](../../../crates/kuku/src/session/runtime/mod.rs)

Attach using an Agent snapshot and its committed Session cursor. Show the latest history page at that boundary first, fetch earlier pages when the reader scrolls back, and follow commits after the boundary. Correlate transient text and tool progress with their Agent and execution. Replace previews with committed results, deduplicate replay by event ID, and recover from a gap or slow observer using durable history. Give each attachment its own target so late updates from a previous selection cannot appear in the current transcript. Read large tool output on demand by the SDK's output ID and byte offset. [SDK observer](../../../crates/kuku/src/session/runtime/observe.rs) · [Retained output](../reference/tools.md)

Provide a bounded preview of the current request's streamed text when attaching to an active Agent, then continue with later updates for that execution. Treat the preview as transient. Preserve the trusted sending Agent address on inputs admitted at Turn start and at later Steps, so the recipient can display their origin.

Reasoning, visible reply text, incremental tool arguments and tool execution can interleave or overlap. Derive each displayed activity from the event that confirms it. A tool runs only after dispatch. Show reasoning activity as a state while keeping private reasoning out of the transcript.

## Terminal interaction

Interactive `kuku` opens a blank fullscreen window in the chosen workspace. Its first explicit send creates the Session. On an empty local data home, offer the existing initialization flow. For a remote configuration error, identify the setting to correct on the server. Show the effective server, workspace and model or tier. Retain the draft while the user corrects a setting. Environment-based credentials belong to the server process that loaded them. When a changed environment requires a restart, point to the service status and restart action. A non-terminal invocation gives a scriptable entry point. Scripting commands preserve their documented output formats and exit behavior. [Configuration](../start/configuration.md) · [CLI](../reference/cli.md)

The terminal uses a flat workspace with a persistent Session identity, visible Turn boundaries, a distinct user message surface and a multiline editor that grows with its contents. Assistant text and tool output have distinct roles. Render Markdown while it streams, with bounded previews, readable tables and one shortcut hint for visible tools. Keep related Agents compact until expanded by keyboard or pointer. An input receipt establishes delivery. Execution phase, streaming text, outstanding decisions and results come from observation of the addressed Agent. Keep presentation tokens in the terminal theme. The composer pairs the kuku ring with a phase label. During work, a gap travels around the ring at one cadence across phases. The ring closes and rests when work ends. Its width stays fixed as text arrives. Distinguish provider-confirmed reasoning from visible reply output and from waiting for the first event. Execution remains an optional footer field. Give an empty Session a recognizable kuku header that contracts to one line once work begins. Summarize Agent listings and Session queries by participants and activity. Detailed inspection retains the original result. [OpenCode Session](https://github.com/anomalyco/opencode/blob/63bfe62c91fb069c97fcdd7a721aa8f7291cbf49/packages/tui/src/routes/session/index.tsx) · [omp transcript](https://github.com/can1357/oh-my-pi/tree/e1ae2cc998efd1ca151b46ebefc0e0dab6c23c63/packages/tui/src/chat) · [Pi terminal](https://github.com/earendil-works/pi/blob/e56d35ce5eceedfa16eaf13a5f01a1f7b7271253/packages/coding-agent/docs/usage.md)

Keep the status line stable while editing. Use one row on desktop. At phone widths, group identity on the first row and workspace and usage on the second when terminal height permits. Use the composer for input and receipt feedback. Fields are configurable. Measure throughput across completed, timed requests for the selected Agent. Compute cache hit rate from requests that report both input tokens and cache-read tokens, using the same paired samples for both totals. Retain known usage on reconnect and identify missing measurements. Show connection and execution failures separately. On Windows, background command tools run without opening a console window.

End each settled Turn with a flat summary card labeled with its Turn number. Show the available duration, input and output tokens, cache hit rate and the count of actual tool calls. It takes no input focus. On narrow terminals, give priority to the transcript text. Beside the activity mark, update the active Turn's elapsed time once per second, for example `1h 05m 54s`. Use the same Turn start across reasoning, reply output and tools, and restore that timing when switching back to the Agent.

Keep the activity line visually stable. Combine related phases and suppress flicker from brief changes while showing errors and requests for attention immediately. When reading earlier output, keep the return-to-latest action beside the composer. Clicking it or pressing Ctrl+End or Alt+Up resumes following the output.

Lead the default status line with the effective model. Group identity and usage in wide default footers, and preserve field order on narrow terminals and in user-configured layouts. Pair color with text for waiting, failure and actions that need attention. Preview status line changes in the editor and keep the saved order in terminal-local preferences. Share spacing, selection and focus styles across the composer and dialogs. Leave space around the composer and footer at ordinary terminal heights. Separate the `To <agent>` recipient from the editable text with clear spacing and keep the Agent name readable on narrow terminals. Pointer input lets users browse and select in Agent, model and execution-detail dialogs. Operations with execution side effects require explicit confirmation with Enter. At narrow widths, give priority to readable transcript and editable input.

## Implementation order

1. **Make the shared execution path work.** Extend SDK admission at the Step and Turn boundaries. Reuse its observation, output and waiting APIs. Implement local service discovery, the server contract and the headless Rust client, then move execution and observation commands in the CLI onto it. Migrate in-tree callers and remove each superseded route or execution path in the same change. Prove first-send retry, two workspaces on one server, busy delivery and detach/reconnect. [Core Direction](core-direction.md)
2. **Deliver the normal terminal entry.** Use Ratatui for layout and Crossterm for terminal events. Keep input editing and transcript rendering independent of network timing. Implement the daily actions above through the shared client. Page older history on demand, bound retained viewport and live updates, and preserve the reader's position while streaming. Restore terminal mode, cursor and paste settings on exit and handled failures. [Crossterm events](https://docs.rs/crossterm/latest/crossterm/event/struct.EventStream.html) · [Ratatui TestBackend](https://docs.rs/ratatui/latest/ratatui/backend/struct.TestBackend.html)
3. **Deliver the installed experience.** Serve the existing WebUI from the same service in the packaged build. Make `kuku web` and a TUI action open the browser on that service, retaining the selected workspace, Session and Agent when available. Keep reusable authentication credentials out of browser handoff URLs and logs. Keep `kuku server` available to run the service explicitly. Use the same addressing, status, reply, steering and cancellation contract. Verify that a browser can continue work from the TUI and return to the terminal. Update install, quickstart, CLI and server reference pages to describe the shipped entry points, and include the new checks in the maintained acceptance selector.
